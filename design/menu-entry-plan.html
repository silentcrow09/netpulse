「装维不加参数」原则收口 — CLI 功能 vs 交互菜单入口缺口审计与补齐方案

1结论摘要

全量比对 argparse 34 个参数位与交互菜单（场景层 + 工程师层）入口后：

11已有菜单等价入口

（本方案补齐）
17调优/输出类
维持 CLI-only（合理）
典型缺口就是 --capture：盯障抓包取证是 v1.8.0 的核心能力，但场景 [7] 盯障与工程师 m 键都调用 run_monitor_mode() 时不传 capture_mode —— 菜单用户永远用不到，只有读 README 记参数的人才能触发。本方案以 5 处菜单改动 补齐全部 6 项缺口，CLI 参数与现有行为完全不动。

2.3 维持 CLI-only（17 项，合理，不进菜单）

输出控制 --json --verbose --no-color --list --json-schema  ·  调优旋钮 --port-force --port-timeout --port-concurrency --iperf3-duration --tcpcc-target --tcpcc-max --nattype-server --max-workers  ·  环境/兜底 --pip-mirror --no-scapy --monitor-target --monitor-load --load-url

其中 --monitor-target / --monitor-load / --load-url 三项有真实价值（盯指定 IP / 压负载盯障），但为保住工程师 m 键「零输入直接跑」的刻意设计，本期不进菜单 —— 装维需要盯指定目标时，用 [7] 的抓包切片 + 报告结论已够用。理由详见 §6。

3设计原则

  1. 场景动作进菜单，参数用 JIT 询问 菜单只新增「做不做这件事」的选择（如 开抓包吗 / 出调试包吗）；「做到什么程度」（MB 上限、节点 ID、URL）只在用户已选定该功能后追问， 且 Enter 永远落在安全默认值上。完全复用 _prompt_for_port_targets 已验证的交互范式。
  2. 不可用先亮状态，再决定问不问 抓包需要 管理员 + Npcap + scapy 三重前置。菜单在询问之前先跑 precheck 并把结论翻译成客户语言亮出来（一行）： 可用 → 出 y/f 询问；不可用 → 只显示原因 + 回车继续，不出选择题（选了也白选，还让装维困惑）。降级语义与现有 CLI 完全一致：统计层照跑。
  3. CLI 路径一行不动 菜单补口只发生在交互函数内部（_run_scene_monitor / _module_menu），run_monitor_mode 等核心函数签名不变； 已显式带 --capture 的 CLI 用户行为字节级不变。

5边界情况一览

场景行为依据 / 一致性
非管理员 / 未装 Npcap / scapy 被禁亮 ✘ 状态行 + 原因，不出选择题，回车继续仅统计层复用 precheck() 的客户文案，与 CLI 降级语义逐字一致
非 TTY（管道 / 脚本调菜单）抓包询问跳过 = 不开启；JIT 询问跳过 = 默认值与 _capture_confirm_once 及 port/iperf3 JIT 的非交互语义一致
已确认过隐私（.capture_ack 存在）不再弹首次确认现有落标记逻辑，零改动
盯障时长输入非法（非数字）沿用现有 clamp：默认 10，范围 1-1440_run_scene_monitor 现行为
CLI 显式带 --capture完全走现有 CLI 路径，菜单代码不参与补口只在交互函数内部
工程师 m 键（高级页盯障）保持零询问直接跑；要抓包走场景 [7]「m = 快」是 v1.6.0 的刻意设计，不回退
d 键无诊断数据提示先跑一次诊断，回车返回（对称 e 键）LAST_RUN 判空
追加 URL 超 8 个上限 / 节点格式非法提示原因并按默认集继续，不中断模块运行沿用 web_targets 上限校验与节点解析

6明确不做（本期范围外）

项不做的理由
--monitor-target 进菜单盯指定 IP 是工程师级操作；给 m 加询问会破坏「零输入直接跑」的刻意设计。装维侧 [7]+抓包已覆盖主场景。
--monitor-load / --load-url 进菜单压负载盯障属专题排障（QoS 限速类），需要理解「负载会占带宽」，放进菜单反而诱导误用。
调优旋钮进菜单（port-force/timeout/concurrency、tcpcc-max、iperf3-duration 等）默认值即最佳实践，暴露旋钮只增加决策负担；CLI 保留给懂的人。
抓包询问里直接暴露 MB 数字输入64MB 默认覆盖 99% 场景；s 子选项够用，避免「64 是什么单位」式困惑。输错 clamp 到 ≥8（现有逻辑）。
场景层 [6] / [8] 空号启用（如 [6]=抓包盯障独立入口）抓包是盯障的属性不是独立场景，拆入口会让「盯障到底选哪个」成为新问题。
