> v1.21.0）的 spec/verify 见 git 历史 `80d73be`。
>
> 2026-11-13 方向确认（Simon）：二期六项全做、按 1→2→3→4→5→6 滚动交付，本特性是
> **第一项 #1 盯障实时窗口**；**抓包取证（--capture）不进 GUI，挂账三期**（终端

## 目标

装维在 GUI 里点「持续盯障」卡片 → 选时长（预设或自定义）、可选自定义目标、
可选主动负载 → 窗口内实时盯（连通状态 / 延迟曲线 / 事件计数）→ 随时点停止
或到时自动结束 → 窗口内直接看盯障报告（三件套照旧落盘）。终端 `--monitor`
全参数行为不变。

**完成后能做什么、怎样看到生效**：双击 exe → 主页出现第 7 张卡「持续盯障」→
点卡片进配置页 → 选 10 分钟 → 开始 → 盯障页实时跳动（四路连通状态 + 延迟曲线）
→ 点「停止盯障」→ 窗口内呈现盯障报告（含图表），`reports/` 目录落下
monitor_*.csv/json/html 三件套。同时 `py netpulse.py --monitor 45` 终端行为
与 v1.21.0 逐字节一致。

## 技术形态

- **盯障内核零改动复用**：GUI 直接组装既有公共件——`MonitorSession(duration_s,
  ext_target, load_url)` + `start()`/`snapshot()`/`stop()`/`build_result()/
  save_monitor_report()`（netpulse.py:13260/13315/13496/13538/13645/13822）。
  **`run_monitor_mode` 与 `MonitorSession` 不修改**（终端专属的 Ctrl+C 捕获、
  抓包耦合、atexit 均不进 GUI 路径）；GUI 自己的轻量编排：daemon 线程内
  「等时长或停止事件 → stop() → build_result(early_terminated=) →
  save_monitor_report()」。
- **数据通道**：新增 `_GuiMonitor` 会话层（线程安全快照，模式同 `_GuiSession`）
  + `/api/monitor/*` 路由（token 闸沿用）。**服务端节流**：进度类计算 ≥2s 一次、
  曲线类 ≥5s 一次（盯障终端的 progress_line 本就每 1s 全量重算，GUI 轮询不得
  加重这个成本）。
- **曲线下发只含滚动窗口**：最近 10 分钟、每流降采样 ≤200 点（SVG 手绘，
  状态色不出 `STATUS_COLORS`）。24 小时上限场景下每秒轮询的服务端成本与
  600 秒同量级（不全量传输、不全量重算——完整事件判定只在结束时跑一次
  `_detect_monitor_events`）。
- **实时事件计数的口径**：盯障页显示的事件计数是**轻量预览**（对最近窗口的
  快照重算，5s 一次）；完整事件列表/根因以结束报告为准（全历史精确判定）。
  页面需注明「完整事件以结束报告为准」。

## 范围

### F1 · 入口与互斥

- 主页场景卡网格新增第 7 张卡「持续盯障」（样式与现场检测卡同档区分，
  说明文案与终端一致：定时监测外网，抓偶发掉线/抖动）。
- **单轮互斥沿用**：同一时段只允许一个网络活动。盯障进行中 → 场景卡/现场检测/
  完整诊断禁用（`/api/run`、`/api/site/start` 返回 409）；场景诊断或现场检测
  进行中 → 盯障卡禁用、`/api/monitor/start` 返回 409。结束后恢复。
- `--capture` 相关一律不出现（本期无抓包）。

### F2 · 配置页

- **时长**：预设 10 分钟 / 30 分钟 / 1 小时 + 自定义分钟数输入；提交前
  钳位到 30–86400 秒（沿用 `run_monitor_mode` 的钳位语义，15427），越界在
  页面回显实际生效值（如「自定义 5 分钟 → 已按最短 30 秒执行」不成立——
  5 分钟合法；示例改为：输入 0 分钟 → 回显按 30 秒执行；输入 2000 分钟 →
  回显按 24 小时执行）。
- **外网目标**：可空输入（占位「默认 223.5.5.5，可改域名或 IP」），透传
  `ext_target`。
- **主动负载**：开关默认关；开 = 60 秒后开始 15s 下载负载（现有
  `_load_worker` 语义），页面上出现负载倒计时提示。
- 说明文案：一句「盯的是什么」（网关/外网延迟丢包 + DNS/TCP 探测，每 5s
  一轮探测、ping 每秒采样）。

### F3 · 盯障页（实时）

- **大数字区**：已运行 / 总时长 + 连通率（gw/ext 流的 ok/total）。
- **四路状态行**：网关 / 外网 / DNS / TCP 各自 ✓/✗ 与丢包/失败计数——口径与
  `progress_line`（13508）同源（服务端组装，页面只渲染）。
- **延迟双曲线**：网关/外网两色线（最近 10 分钟滚动窗口，≤200 点/流，
  SVG 手绘，5s 刷新）；丢包点以色点标注；图例可读。
- **事件计数条**：中断 / 高延迟 / 抖动 / DNS 失败 预览计数（5s 节流轻量重算）
  + 一句「完整事件以结束报告为准」。
- **停止按钮**：等价终端 Ctrl+C——提前结束、报告标注「提前终止」
  （`build_result(early_terminated=True)`），确认弹窗防误触。
- 负载提示：开了主动负载时显示「60s 后开始 15s 下载负载」倒计时。

### F4 · 结束与报告

- 到时或停止 → `stop()` → `build_result()` → `save_monitor_report()` 三件套
  落盘 `_report_dir()`（`monitor_YYYYmmdd_HHMMSS.*` 命名不变）。
- 窗口内整页内嵌盯障报告 HTML（现有 canvas 图表复用，经
  `GET /api/monitor/report` 输出，模式同 `/api/report`）。
- 结论条：verdict / 结论 / 建议（`_monitor_conclusion` 产物透传，不自算）+
  「打开报告文件夹」按钮 + 「返回主页」。
- 报告在进程内可反复查看（最后一次盯障）；新开一轮生成新报告。

### F5 · 数据通道与安全红线

- 全部新路由过 token 闸；GUI 轮询节流（progress ≥2s、曲线 ≥5s）服务端实现，
  页面 1s 轮询只读缓存，不触发重算。
- 新代码不得直接读写全局 `LAST_RUN`（盯障链路本就不用它）。
- 状态语义色唯一来源 `STATUS_COLORS`；✓/✗ 点色不得另立色值。
- 页面动态数据一律 `textContent`，禁止 innerHTML 插值（沿用 v1.21.0 闸）。
- 盯障与诊断互斥在服务端会话层实现（`_GuiSession` 与 `_GuiMonitor` 共享
  「网络活动忙」判定），HTTP 层 409 与页面禁用双保险。

### F6 · 本期明确不做（挂账）

抓包取证窗口化（三期议）、#2 模块勾选面板（二期第 2 项）、诊断取消/续跑、
历史报告浏览、多语言、GUI 自动更新。终端 `--monitor --capture` 不受任何影响。

## 不变量（回归红线）

- 终端 `--monitor` / `--monitor-target` / `--monitor-load` / `--load-url` /
  `--capture` / `--capture-mb` / 菜单入口 `m` 行为与 v1.21.0 **逐字节一致**；
  `run_monitor_mode` / `MonitorSession` 零修改（GUI 只读复用公共件）。
- 盯障报告三件套命名与内容结构不变（`monitor_*.{csv,json,html}`）。
- 全量 pytest 保持绿；`tests/` 现有用例零改动通过。
- GUI 既有五界面（主页/进度/报告/现场检测/联网点）行为不变，主页新增卡片
  不破坏既有布局契约。
