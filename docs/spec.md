# 网口对照表（端口定位）

> 本文件是**需求的唯一来源**。实现方案见交付说明，验收标准见 `docs/verify.md`。

## 目标

装维上门时，打开完整版报告就能一眼看出**哪个网口是承载默认路由的出口口、哪个是内网接入口、哪个是 WiFi 口、哪个是虚拟网卡、哪个没插线或协商速率掉了档**（千兆协商成百兆）。现场交付给客户的一页版报告第 1 页同步给出一行摘要，不必展开完整报告就能判断"网线插错口 / 链路降速 / 虚拟网卡干扰"。

JSON 报告新增顶层 `port_map` 字段，技术员可拿去做二次分析。

## 范围

1. `linkspeed` 模块结果新增 `egress_interface` 字段：承载默认路由（`0.0.0.0/0`）的网卡别名。
2. 抽出共享判定 helper `_linkspeed_tier()`，把散落在 `_verdict_linkspeed` / `_metrics_linkspeed` / `_tech_appendix_section` 三处的速率档位阈值与 VPN 虚拟网卡关键字表统一为单一来源。
   - 现状：三处各写一份；VPN 关键字表已出现 `forticl`（_verdict_linkspeed）与 `forticlient`（_metrics_linkspeed）不一致；`_tech_appendix_section` 又手抄了一遍阈值数字。本期合并，消掉这份漂移。
3. `build_report` 产出 `report["port_map"]`：逐网口的类型、状态、协商速率、角色、提示。
4. 完整版客户报告新增一级章节「网口对照」。
5. 一页版客户报告（brief_v2）第 1 页 KPI 区下方新增一行摘要。
6. JSON 导出新增顶层 `port_map` 字段；`schema/netpulse-result-v1.2.json` 同步声明。

## 不做什么

- 不新增 Probe，不新增 `MODULE_REGISTRY` key —— 属既有 `linkspeed` 模块的结果增强 + 报告层聚合。
- 不采集双工（full/half duplex）与物理介质类型：需要 `Get-NetAdapterAdvancedProperty` 且要管理员权限，本期不做。
- 不判定交换机侧的「上联口 / 管理口 / trunk 口」：Windows 客户端侧拿不到该信息，不臆造。
- 不改一页版客户报告（brief v1）。
- 不动既有 `port` 模块：它是 TCP/UDP 端口可达性探测，与物理网口无关，术语不要混淆。
- 不新增 `LAST_RUN` 依赖。
- 不改健康分口径：`port_map` 不产生新的模块级 issue，不参与扣分。
- 不改 `arp` / `route` 模块的解析逻辑。
- 不合并 `gateway` 模块与出口口两套「选默认路由」算法（见「术语 · 出口口」的差异说明）。

## 硬约束

- **性能**：不新增任何系统命令族。`linkspeed` 只允许复用既有 `_default_route_if_mtu()`（内部 2 条 PowerShell），该调用与 `mtu` 模块共享 `_CMD_CACHE`（TTL 5 秒），并行跑时通常命中缓存。单独跑 `linkspeed` 时增加耗时 ≤2 秒。
- **确定性**：同一台机器、同一网络状态下，`port_map` 的角色判定必须唯一且可复算；出口口判定必须复用 Windows 自身的路由 metric 语义，不得另造一套。
- **展示位置**：完整版里必须是**独立一级章节**，不得塞进 `linkspeed` 的折叠卡 —— 有根因时模块卡默认只展开首要根因模块，塞进去装维看不到。
- **一页版页数**：brief_v2 仍须为 A4 2 页，加摘要后必须用 `tests/_a4_pagecheck.py` 实测确认。
- **阈值单一来源**：速率档位阈值只允许存在一份实现，新表复用共享 helper，不得再写一份。
- **转义**：文本节点用 `_html_esc`；任何属性值（`title=` / `data-hint=` / `class=` 等）用 `_html_attr`。网卡名、网卡描述是用户可自定义的不可信输入，必须转义。
- **离线可开**：不引入任何在线资源；样式进 `CSS_CUSTOMER_REPORT` 字面量，**不得把整块 CSS 改成 f-string**（里面全是 `{{ }}` 双花括号）。
- **schema 一致**：JSON 导出字段与 `schema/netpulse-result-v1.2.json` 必须同步，`tests/test_schema_export_consistency.py` 必须仍全绿。

## 术语

- **网卡别名**：Windows 的 `Get-NetAdapter.Name`，与 `Get-NetIPInterface.InterfaceAlias` 同名，是全仓唯一可用的网卡身份主键（`linkspeed` 的 `adapters[].name` 与 `mtu` 的 `local_mtus[].interface` 靠它 join）。
- **出口口**：承载默认路由（`0.0.0.0/0`，按 RouteMetric 取最优）的那个网卡。判定复用既有 `_default_route_if_mtu()`。
  - *与网关模块的差异*：`gateway` 模块用 `_pick_best_gateway()` 从 `route print` 的候选里挑（优先同子网），出口口用 `Get-NetRoute` 按 metric 挑。单默认路由场景两者一致；多默认路由场景可能不同 —— 属既有口径差异，本期不合并，章节说明里写明「出口口按 Windows 最优路由 metric 判定」。
  - *角色优先级*：**出口口优先于虚拟口**。VPN/隧道网卡承载了默认路由时，它就是当前上网用的那个口，角色标「出口口」，提示里说明是隧道在承载。
  - *出口口没连上*：仍标「出口口」（状态列显示未连接），提示「默认路由指向它, 但当前未连接」—— 装维需要知道该去查哪块口。
- **内网口**：已连接（状态 Up）的**物理**有线网卡，且不是出口口 —— 这是**推断角色**，不代表它真的连在交换机上。
- **WiFi 口**：`linkspeed` 判定为无线的网卡。
- **虚拟口**：**软件虚拟网卡**（VirtualBox / Hyper-V / ZeroTier / WSL / 环回 / VPN 客户端等），且不是出口口。判定用 Windows 权威的 `Get-NetAdapter.Virtual` 属性 + VPN 产品关键字。
  - *与档位判定是两个轴*：档位（是否扣分）只认 VPN/隧道产品关键字 —— VirtualBox 这类本地桥接口的速率仍按有线算（它不影响客户宽带）；「是不是物理口」才用 `Virtual` 属性。
  - *类型标签全报告统一*：「虚拟」在对照表、linkspeed 模块卡、探测器 issue 里是同一个词义（不是物理插口）。软件桥接网卡没有网线，报告里不得再说「有线」或「检查网线/水晶头」—— 装维会照着去查一根不存在的网线。**档位、issue 的类型/严重度/数量与健康分口径不变。**
  - *对照表里虚拟口的档位列记 `n/a`（不适用）*：既不是「正常」也不是「异常」。报正常会让一页版摘要说「各口速率正常」，而 linkspeed 模块卡同时在说这块口的档位异常 —— 同一份报告自相矛盾；报异常则把虚拟桥接口的速率误当成物理链路质量问题。这一格不参与健康分，只表示「拿它判物理链路没意义」。
- **未插口**：状态不是 Up 的网卡。未连接时**不展示协商速率**（驱动报的是上次连接留下的陈旧值），档位记 `n/a`（无速率可判），不是「ok」。
- **未判定**：取不到默认路由出口（`Get-NetRoute` 失败 / 本机无默认路由 / 出口别名对不上任何网卡）时，无法确定某块有线口是不是出口口 —— 此时有线口标「未判定」，**不瞎标成「内网口」**（那是断言装维已知的事，而事实未知）。同名网卡出现多行时，除第一行外也标「未判定」（出口口必须唯一）。
  - *提示列的补写规则*：「未能确定默认路由出口, 角色待判定」**只在档位提示为空时**补写。档位已有提示（如「协商到百兆, 千兆环境应达 1000 Mbps」）时保留档位原文 —— 覆盖掉会让最关键的那句提示从报告里消失。
- **一页版摘要**：一行，口径与对照表一致。
  - *速率精度一致*：摘要与对照表用同一个格式化函数（整数不带小数，非整数保留一位小数），不得一边 `115.6 Mbps` 一边 `116 Mbps`。
  - *不得替未连接的口宣称正常*：未连接的口档位是 `n/a`，没有速率可判。物理口一根没插时摘要要说「无在线物理口」并报「N 口未连接」，不能说「速率正常」—— 交到客户手上的报告不能假绿。
  - *口数与对照表的列一一对应*：「N 口未连接」按状态列统计（已禁用不算未连接），「N 个虚拟网卡」按类型列统计。按角色列统计会漏掉两处 —— 未连接但承载默认路由的那块口（角色是「出口口」）、未连接的虚拟网卡（角色是「未插口」）。
- **档位**：速率健康分档。有线 ≥1000 正常 / ≥100 警告 / <100 异常；WiFi ≥150 正常 / ≥54 警告 / <54 异常。
- **降速口**：档位为警告或异常的有线口，提示文案沿用 `_metrics_linkspeed` 现有措辞，不另造说法。
