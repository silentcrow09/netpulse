## 目标

把终端「高级选项 → 模块单测菜单」的能力搬进 GUI：按分类勾选任意模块组合 →
一键运行 → 复用既有进度页与报告页。装维不必回终端就能单测某个可疑模块
（如只测 DNS、只测 MTU），或自由组合诊断。

**完成后能做什么、怎样看到生效**：主页进高级面板 → 勾「DNS 诊断 + MTU 检测」
→ 点「运行所选 (2)」→ 既有进度页推进（label 显示「模块组合 (2 项)」）→
报告页呈现全规则根因分析 → 导出文件名含「模块组合」。同时终端菜单 `9`
与 `--list` 行为逐字节不变。

## 技术形态

- **执行管线零新增**：勾选组合以 `keys` 列表进 `_GuiSession` 既有
  `run_diagnostics(keys, parallel=True, ...)` 管线——独占模块（测速系）自动
  并发批后串行、压测 tcpcc 单独选中允许（全部既有调度语义，netpulse.py:16941/
  15584），GUI 不重写任何调度。
- **根因口径**：任意组合按既有语义走 `diagnose(rule_filter=None)` 全规则评估
  （`PROFILE_RULES` 无对应键即落全规则，netpulse.py:2583/2599——组合不伪造
  场景规则集，报告诚实按全规则出）。
- **API**：`POST /api/run` 扩展双形态——`{profile}`（现状不变）或
  `{keys: [...]}`（新，互斥出现）；服务端白名单校验 `keys ⊆ 全部模块 key`
  且非空（非法 → 400），经 `_gui_net_busy()` 互斥（409 同现状）。
- **`_GuiSession.start` 扩展**：接受 `keys` 形态（新参数或键位区分），内部
  `label = "模块组合 (N 项)"`；`_run_diag` 的 `rf` 逻辑天然兼容
  （组合不在 `DIAGNOSE_PROFILES` → None）。

## 范围

### F1 · 入口（选型结论：变体 A）

- 主页「完整诊断」次级行旁新增次级文字入口「高级模块组合 ›」；
- 面板本体三视图不变，见 F2。

### F2 · 面板视图（#view-modules）

- **三分类分组**（`MODULE_CATEGORIES` 同源：基础信息[a] 6 / 宽带测速[b] 5 /
  故障诊断[c] 13），每组：分类名 + 副题 + 该组模块复选列表（中文名 + 勾选框；
  数据取 `/api/scenarios` 载荷扩展的 `module_catalog`（key/中文名/分类），
  不另立清单）。
- **组操作**：每组「全选 / 清空」；顶部「全选 / 清空 / 反选」+ 已选计数。
- **压测警示**：勾选 `tcpcc` 时该项红字标注「压测：短时建立大量连接，
  勿对客户网络使用」+ 运行前 confirm 确认（勾了 tcpcc 才弹）。
- **内联配置（可空）**：`port` 勾选时展开目标输入（格式同终端 `host:port` 或
  `host:port1-port2`，多个逗号分隔；留空 = 既有语义——模块报「未提供目标」
  警告）；`iperf3` 勾选时展开服务器输入（留空 = 「未检测」）。不填就不拦，
  结果口径与终端一致（诚实降级，不伪造跳过）。
- **Ookla 对照开关**（默认关，勾了 `speedtest` 才显示）：开 =
  `use_speedtest_net=True`（终端 CLI 同款默认关语义；菜单强制开的口径不进 GUI）。
- 底部：「运行所选 (N)」主按钮（N=0 禁用）+ 返回。

### F3 · 执行与报告

- 运行 → 既有进度页（复用 `pollOnce` 管线，label=「模块组合 (N 项)」）；
  `port` 有内联目标时启动前写入 `PORT_PROBE_CONFIG`（格式校验失败 → 400
  留在面板报错，不启动）。
- 完成 → 既有报告页（全规则根因）+ 导出四件与场景一致，文件名 label 同源。
- 单轮互斥沿用：面板运行中其余入口禁用（409）；反向同理。

### F4 · 数据通道红线

- `/api/scenarios` 载荷新增 `module_catalog`（key/中文名/分类字母）——数据
  唯一来源 `MODULE_REGISTRY`/`MODULE_CATEGORIES`，页面不内嵌清单。
- 新代码不碰 `LAST_RUN`；token 闸覆盖全部新流量；`textContent` 纪律；
  状态色不出 `STATUS_COLORS`。
- `keys` 白名单校验在服务端（`_gui_net_busy` 同锁内查+置位），防绕过。

### F5 · 本期不做（挂账）

组合方案的保存/命名复用、模块级参数化配置（除 port/iperf3 内联两项）、
批量队列（跑完一轮自动跑下一轮）、终端菜单的 GUI 化改造（终端菜单原样保留）。

## 不变量（回归红线）

- 终端 `_module_menu` / `parse_choice` / `_parse_keys` / `--list` /
  `_print_module_list` 行为**逐字节不变**（GUI 只读消费注册表常量）。
- 既有 GUI 七卡、场景诊断、现场检测、盯障行为不变；`/api/run {profile}` 形态
  向后兼容（现有测试零改动通过）。
- `MODULE_REGISTRY` / `MODULE_CATEGORIES` 常量不重构（GUI 只读）。
- 全量 pytest 保持绿。
