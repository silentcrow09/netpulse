# 诊断中途取消 / 续跑（v1.24.0）· 需求规格

> 本文件是**需求的唯一来源**。验收标准见 `docs/verify.md`。前一特性（模块勾选高级面板
> v1.23.0）的 spec/verify 见 git 历史 `c0f0e72`。
>
> 2026-11-13 方向确认（Simon）：二期六项全做滚动交付，本特性是**第三项 #3 诊断中途
> 取消/续跑**。三个口径已拍板：
>
> 1. **软取消** —— 点了停止后不再启动新模块，手头这一项跑完就出报告（最长约 3 分钟）；
> 2. **复用已完成结果** —— 续跑只跑没测过的那几项，测完的直接复用；
> 3. **跨重启可续** —— 停止时把已完成的结果落盘，关窗、退出程序都不丢。
>
> 界面设计稿：`design_ref/gui/cancel_resume_design_v1.html`（含两套停止交互变体，
> 选型结论见 §F1）。

## 目标

让装维在一轮诊断跑到一半时可以**停下来**，而且**不白跑**：

- 现场网络差、测速模块卡住时，不必干等整轮跑完；
- 停下来的这一轮，已经测完的项目**保住**（照样出一份部分报告），之后可以**接着跑**
  剩下的；
- 关掉窗口、退出程序也不丢 —— 下次打开 NetPulse 提示「上次没跑完，接着跑？」。

**完成后能做什么、怎样看到生效**：主页点「网络很慢」→ 进度页右上出现「停止」→ 点它
并确认 → 页面提示「正在收尾，等当前项目跑完就出报告（最长约 3 分钟）」→ 手头那项跑完
→ 出部分报告（首屏写明「检测范围 12/24 项」，没跑的项目显示「未检测」）→ 进度页出现
「继续跑剩下的 12 项」→ 点它 → 只跑剩下 12 项 → 出完整报告（24 项全覆盖）。中途关窗
重开，主页顶部出现「上次诊断没跑完」横幅，点「接着跑」同样能续。

## 技术形态

- **取消闸加在调度层**：`run_diagnostics` 新增仅关键字可选参数 `cancel_evt=None`，
  透传给 `_run_diagnostics_parallel` / `_run_diagnostics_sequential`。默认 `None` →
  行为与 v1.23.0 逐字节一致（终端零影响）。闸位两处：并发段「派下一个模块之前」、
  独占段「进入测速类模块之前」。
- **软取消语义**：收到停止请求后不再启动新模块；**已经在跑的模块等它自己跑完**（模块
  内部没有中止开关，超时后放弃结果的老机制不动）。并发段最多 4 项同时在跑 → 最长等
  其中最慢的一项（≤150 秒）；独占段最长 180 秒。总上限约 3 分钟。
- **部分报告几乎不用改报告层**：`run_diagnostics` 返回的 run dict 里 `results` 只含跑完
  的模块，`keys` 仍是请求全集 → `build_report` 既有逻辑（`res = run["results"].get(key,
  {})`、`status_map.get(key, "未检测")`）天然产出「未检测」占位。这与「场景诊断只跑部分
  模块」是同一种形状，报告层不用为「没跑」新增状态值。
- **报告首屏的覆盖数字要改一处**：客户版报告 Hero 的「检测范围」当前取
  `selected_modules`（= 请求了几项），提前结束时会把 12/24 写成「24 项全覆盖」。改法：
  实际跑完的项数从 `tech.raw_results` 的条目数取（唯一事实来源），只有「实际跑完 <
  请求数」时才走新分支。**既有全部报告输出逐字节不变**（今天 requested == ran，恒成立）。
- **续跑需要 `build_report` 显式收 run**：`build_report` 现在只认全局 `LAST_RUN`。新增
  仅关键字可选参数 `run=None`（`None` → 沿用 `LAST_RUN`，既有调用点零影响），供续跑合并
  后显式传参 —— 方向与仓库收口规则「存量引用只减不增」一致（新代码不碰全局）。
- **续跑点落盘**：`%LOCALAPPDATA%\NetPulse\resume.json`（与既有 `log_report.json` 同目录
  约定）。单文件，最多保留一个未完成轮次。
- **结果累积**：`progress_cb` 的 done 事件扩展一个**可选** `result` 字段（该模块的完整
  结果 dict，含过渡键 `_evidence`）。既有消费者零影响；终端不传 `progress_cb`，行为不变。
- **续跑合并**：已保存的状态与结果 + 新一轮的结果 → 合并成一份完整 run dict（`keys` 取
  原始请求全集，`results`/`status` 取并集，`evidence` 走既有 `_extract_evidence_map`，
  `duration_ms` 为两段之和）→ `build_report(run=merged)`。
- **报告级备注**：`build_report` 新增仅关键字可选参数 `note=None`，写入 `report["note"]`，
  由客户版报告 Hero 渲染成一行；`render_report_json` 同步导出，`schema/` 与一致性测试
  按 AGENTS.md 的既定流程同步（`additionalProperties: false`，漏改必红）。

## 范围

### F1 · 进度页「停止」（变更）

- 进度页右上角新增「停止」按钮（红色描边，口径与盯障页的「停止盯障」一致）；
- 点击先弹确认：「确认停止本轮诊断？已完成的项目会保留，之后可以接着跑。」；
- 确认后：按钮变成「正在收尾…」并禁用；进度区出现提示「已停止调度，等当前项目跑完
  就出报告（最长约 3 分钟）」；
- 收尾期间其它入口（现场检测 / 盯障 / 新诊断）一律 409，互斥不放宽；
- 停止请求幂等：不在跑 → 400「当前没有进行中的诊断」。

**选型待定**：停止按钮的落位与「已停止」后的呈现有两套变体，见设计稿第 1/2 节；
以设计稿标注的推荐变体为默认，Simon 可在方案确认环节改选。

### F2 · 停止后的部分报告（变更）

- 手头那项跑完后立刻出报告，不等剩余项；
- 报告首屏写明实际覆盖：「检测范围 12/24 项」，并注明「本轮提前结束, 12 项未检测」；
- 没跑到的模块在报告里显示「未检测」，**不扣分**（未检测扣 0 分，既有 `SCORE_PENALTY`
  口径）；
- 部分报告**可导出**（HTML / PDF / JSON，口径与正常轮次一致）。

### F3 · 续跑（新增）

- 进度页（已停止态）出现「继续跑剩下的 12 项」按钮；
- 续跑只跑没测过的模块，测过的**复用**上次结果；
- 进度页的模块网格仍显示全部 24 项（已测的显示原状态，没测的走进度）；
- 合并后出完整报告，报告里注明「本轮为续跑，部分项目的数据来自上一次运行（时间）」；
- 续跑轮次的标题显示为「网络很慢（续跑）」，导出文件名同源；
- 续跑正常跑完 → 删除续跑点（不再提示）。
- 「继续跑」入口**只在真的能续时给**：已停止 · 非现场检测 · 续跑点确实落盘成功 ·
  还有没测的项 · 未落盘失败。少一条就不给入口（假入口点了只会报错）；
  一项都没测完就停、或停止请求落在最后一个模块之后（其实全测完了）都不给入口。

### F4 · 跨重启续跑（新增）

- 停止后、以及**关窗时**（诊断还在跑），把已完成部分落盘；
- 下次打开 GUI：主页顶部横幅「上次诊断没跑完（网络很慢 · 实检 12/24 项 · 11-13 15:30）」
  + 两个按钮「接着跑」/「重新开始」；
- 「重新开始」= 丢弃续跑点，不提示；「接着跑」= 直接进续跑；
- 续跑点最多保留 7 天，过期自动清理（避免拿两天前的数据当现状）。
- 只保留最近一个；**新一轮停止时覆盖**旧点；普通新一轮跑完**不删**旧点
  （删了等于把上一轮已测完的成果抹掉）；全都测完的轮次不写点（没有可续的）。

### F5 · 关窗不丢（新增）

- 诊断进行中关窗：先把已完成部分落盘，再退出（在跑的那项算没测完，下次重跑）；
- 页面在关窗前提示「诊断还在跑，关窗会保留已完成的 12 项」。
- **收尾中（已点停止、等当前模块跑完）关窗同样要落盘并退出**——那一轮已经在收尾，
  不许卡住（否则程序在后台常驻、成果白测）。

### F6 · 现场检测流程（变更，降级）

- 现场检测的诊断阶段同样可以「停止」；停止后照样能出部分报告并导出；
- 现场检测**不支持续跑**（现场流程的结论要一次跑完才成立）—— 停止后只能「重新检测」。
  页面明确说明，不假装能续。

### F7 · 终端零变化（约束，不是功能）

- 不加 Ctrl+C 取消；`--diagnose` / `--json` / 终端菜单 / 退出码逐字节不变；
- `run_diagnostics` 新参数默认 `None` → 终端调用点行为不变。

### 非范围

- 不做「暂停」（只能整轮停下，不能半途接同一个模块）；
- 不做多个续跑点（只保留最近一个）；
- 不做抓包取证（挂账三期）；
- 不改模块内部的检测逻辑（模块仍按既有超时与降级策略跑）。

## 风险与已知限制

| 风险 | 处理 |
|---|---|
| 停止请求落在独占段（测速） | 等该项跑完，最长 180 秒；页面提前说明「最长约 3 分钟」 |
| 在跑的模块停不下来 | 不硬杀（会留下载残留、污染续跑测速），只停**调度** |
| 续跑点文件损坏 | 读失败 / 结构非法 → 当作没有续跑点，不崩溃，页面不提示 |
| 落盘失败（磁盘满 / 无权限） | 提示「续跑点保存失败」，但不影响当轮报告与导出 |
| 续跑合并的两段数据来自不同时间点 | 报告里注明来源与时间；GUI 续跑入口列出剩余项 |
| 续跑点被新的一轮覆盖 | 只保留最近一个（设计如此）；开始新一轮不立即删除旧点，新一轮停止时覆盖 |

## 不变的东西

- 终端全部行为（菜单 / `--diagnose` / `--json` / 退出码）；
- `MonitorSession` / `run_monitor_mode` / `_module_menu` / `MODULE_REGISTRY` /
  `MODULE_CATEGORIES` 零修改；
- 报告渲染层除 Hero 的覆盖数字分支与新增 `note` 一行外零改动，既有报告输出逐字节
  一致（按 AGENTS.md 的固定 fixture 逐行 diff 验证）；
- 状态色唯一来源 `STATUS_COLORS`，本特性不新增模块状态值（「未检测」复用既有值）；
- 零新增第三方依赖，仅标准库。
