# 控制台界面现代化（方案 B）· 需求规格

> 本文件是**需求的唯一来源**。视觉参照 `design_ref/console_ui_redesign.html`（方案 B 区画面），
> 验收标准见 `docs/verify.md`。前一特性（环回测速）的 spec/verify 见 git 历史 `ecb3bf5`。
>
> 2026-11-12 选型确认：方案 B（现代重排）+ 接受完成屏快捷键与「»」提示符 + 分两批实施。

## 目标

双击 exe 打开的 CMD 窗口呈现统一的现代视觉语言：一套边框、一套语义色板、有层次的菜单、
实时的诊断进度、结论前置的完成屏。装维在现场快进快出时，**先看到结论，再看细节**；
老机器（Win7 老 conhost）不出现乱码，自动降级为无色静态形态。

**怎样看到生效**：运行 `NetPulse.exe`（无参数）→ 首页变为闭环框横幅 + 分区菜单；
跑任一场景 → 顶部出现整体进度条、完成屏出现健康分区与状态分布条；
`--json` / 管道输出与改造前逐字节一致。

## 批次 1 · 修复与地基（半天，可独立随下次发版）

### 1. VT 不可用自动降色（修 Win7 乱码）

`_cli_enable_vt()` 确认失败时（Win7 老 conhost 不认 `ENABLE_VIRTUAL_TERMINAL_PROCESSING`、
输出重定向、无控制台），同步把 `_C_NOCOLOR` 置为 `True` —— 老机器不再把 ANSI 码按字面
打成 `←[90m` 乱码。约束：

- VT **可用**时颜色行为与现在完全一致（不因修复变灰）。
- `--no-color` 仍可强制无色；两开关叠加结果仍是无色。
- 返回值语义不变：`_menu_clear()` 据此退化 cls/clear 子进程的逻辑照旧。

### 2. 终端状态色板语义对齐

`STATUS_STYLE`（终端侧唯一状态色来源）与报告层 `STATUS_COLORS` 同语义对齐：

| 状态 | 报告层（HTML） | 终端（现状 → 对齐后） |
|---|---|---|
| 完成 / 正常 | 绿 | 绿（不变） |
| 警告 | 橙 | 黄（不变，16 色基线最近似） |
| 异常 | 红 | 红（不变） |
| 错误 | 深红 | 红（不变，16 色基线无深红） |
| **超时** | **中性深灰 #334155（"没跑完，不是坏"）** | **红 → 灰**（语义错配修正：超时不是故障，不该与异常/错误同级刺眼） |
| 未检测 | 灰 | 灰（不变） |

`STATUS_STYLE` 覆盖 `STATUS_BAR_ORDER` 全部 6 个状态键。

## 批次 2 · 视觉重排（约 2 天）

### 3. 横幅（场景菜单头 + CLI banner）

- `=`×60 等号横线 → **闭环细框**（`┌─…─┐` / `└─…─┘`），标题嵌框内：`NetPulse vX.Y  网络诊断（场景模式）`。
- 权限徽标弱化：普通权限 = 灰字「· 普通权限」；管理员 = 亮色提醒。
- 本机 IP / 网关 / DNS 收进框内第二行；公网 IP 与归属地**查到后**在框外补一行灰字，
  查不到不占位（不再固定两行硬挤，窄窗口不折行）。

### 4. 场景菜单

- 双分区：「按问题选场景」（1-5）与「工具与报告」（6/7/9/A）。
- 菜单项为**无底色菜单行**（键号青 / 名称亮白 / 副行灰，结构与设计稿卡片一致）
  + **说明副行**（一句话讲清场景做什么，文案由场景模块清单生成，不新增能力
  承诺）。〔修订 2026-11-12 实机反馈：原方案 ANSI 100 亮黑底在经典 conhost
  配色下是一条明显灰带而非暗色卡片（该观感只在 WT 深色主题成立），用户拍板
  移除铺底，只保留结构与对齐 —— 与高级菜单素色风格一致。〕
- 列宽按 `_disp_width`（CJK=2）计算严格对齐；按终端实际宽度自适应，
  窄窗口收起说明列。菜单编号与快捷键语义不变。

### 5. 诊断进度

- VT 可用：顶部**单行整体进度条**（`█░` 块字符 + `n/23` + 当前项名，`\r\033[K` 刷新）
  + 状态列表逐项重绘：完成=绿✓ / 警告=黄⚠ / 错误=红✗ / 进行中=灰…（色 + 符号双编码）。
- VT 不可用：自动回退现状的静态两列列表（功能零损失）。
- 测速类独占模块仍按既有规则串行，进度条如实反映顺序，不改变任何诊断口径。

### 6. 完成屏

- **健康分区**（框内）：大号分数 + 等级徽章色 + 分数条 + 状态分布条。
  数据与 HTML 报告 hero / 状态分布条**同源**（`report["health"]`、`report["counts"]`
  扣分口径），框内一行小字写明豁免口径，避免「有红但满分」的口径困惑。
- 根因区（`_print_diagnosis`）排版照旧，报告路径行加 `📄 →` 前缀。
- **下一步快捷键**：`[Enter] 返回菜单 / [H] 打开报告`（[H] 打开已生成的 HTML 报告；
  设计稿中的 [J] 生成 JSON **不做**——与既有报告询问流程打架，以本 spec 为准）。

### 7. 提示框统一

scapy 缺失框、异常上报告知框、抓包授权确认框统一为「标题嵌框 + 闭环 + 宽度按内容自适应」，
共用一个框渲染函数（内部走 `_disp_width`，与 v1.19.x 告知框修复同源），消灭手工排框。

### 8. 输入提示符统一

全部 input 提示统一为「… » 」格式；确认选项统一「[Y=… / N=…]」配色（绿可 / 红否）。

### 9. 实施约束

- **16 色基线**：全部视觉用 ANSI 16 色实现，不引入 truecolor。
- **字符白名单**：只用点阵字体有字形的字符（`┌┐└┘│─ ✓✗⚠…█░■● ·»`）；
  不用圆角框 `╭`、Braille `⠋`（方案 C 特性，本 spec 不含）。
- **宽度**：一切对齐/补边走 `_disp_width`；终端宽度取 `shutil.get_terminal_size`。
- 新增渲染函数配单测（VT 两种形态各测）；既有测试行为断言不动。

## 保持不变

菜单编号/快捷键语义 · 场景对应模块组合与口径 · 独占模块串行规则 ·
健康分扣分口径（异常-20/错误-30/超时-10/警告-2/未检测 0）·
`--json` / 管道输出（stdout 纯 JSON、人读输出走 stderr）·
提示文案措辞（只动排版；涉及文案改动单独列给用户确认）。

## 降级矩阵

| 宿主 | 形态 |
|---|---|
| Win10+ conhost / Windows Terminal | 完整形态（框 + 分区菜单 + 动态进度条 + 健康分区） |
| Win7 老 conhost | 无色 + 静态列表（批次 1 后不再有乱码） |
| 管道 / 重定向 / `--json` | 无色，人读输出走 stderr，stdout 纯 JSON 不变 |
| `--no-color` | 永远强制无色（优先级最高） |
