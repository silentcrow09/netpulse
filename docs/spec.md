## 目标

装维拿到 HTML 报告后，能一眼分清「真故障」和「工具自己判出来的假警报」，并看清总分是怎么扣出来的。

**怎样看到生效**：重跑一次全量诊断 → 打开新 HTML 报告，同时满足：

1. MTU 模块不再出现「到 xxx 的路径 MTU (1499) 小于标准 1500」（本机实测路径 MTU = 1500）；
2. IPv6 模块徽章由「异常」变「提示」，且不出现在待办清单里；
3. DNS 模块显示「当前 DNS (223.5.5.5) 实测 ~5 ms」，不再出现「尝试更换 DNS 服务器 (阿里/腾讯/114)」；
4. 顶栏 IPv6 地址带「出口（经代理/隧道）」标注，并注明非本机原生 IPv6；
5. 每个模块卡标题栏右侧显示该模块的扣分标记，评分旁有一行合计算式；
6. 顶部诊断条不再写「✓ 无故障 / 整体高置信度, 评估 8 条规则」。

## 范围

### F1 · MTU 分片风险误报 + 可执行命令

- 二分收敛后增加**确认探测**：收敛路径 MTU ≥ 1492 时，对标准载荷 1472 字节（DF 置位）再打 3 次 ICMP。
  - ≥1 次有回复 → 路径 MTU 判为 1500、`fragmentation_risk=False`，记录确认探测次数与成功数；
  - 3 次全失败 → 保留二分收敛值为真实路径 MTU，`fragmentation_risk=True`。
- 收敛路径 MTU < 1492 时不追加确认探测（明显受限，直接判真）。
- **报警门槛**（两条同时成立才报）：
  1. 确认探测后仍 `path_mtu < 1500` **且** `1500 - path_mtu ≥ 8`（差 1~7 字节写进技术细节并标注「测量不确定，不作故障处理」）；
  2. **路径 MTU < 本机出口接口 MTU** —— 本机确实能发出比路径承载更大的包才谈得上分片。若接口本身就配成 1492（PPPoE）、路径也是 1492，两边一致 → 主机发不出超限包，不是故障。
- 本机接口 MTU < 1500 本身**不是故障**（PPPoE 接口就配 1492）→ 降为信息级条目（v1.20.0 实施时补充：原口径把它算作警告，会让 PPPoE 用户长期白挂一个警告）。
- 报警时，问题建议必须同时给出三段内容：
  - **核实命令**：`ping -f -l 1472 -n 5 <目标>`（5 次全通即路径 MTU = 1500，与本工具判定口径一致）；
  - **修复命令**：`netsh interface ipv4 set subinterface "<出口接口名>" mtu=<实测路径 MTU> store=persistent`，接口名取 `local_mtus` 中 `egress=True` 的接口（取不到时写明「默认出口接口」并说明如何查）；
  - **复查动作**：`netsh interface ipv4 show subinterfaces` + 重跑 `netpulse mtu`。
- 修复命令的写法**复用**既有 `_rule_mtu_blackhole`（netpulse.py:2084）里的 netsh 生成逻辑，不另立一份。
- 命令要能直接粘去执行：接口名过 `_safe_iface_name` 白名单、目标地址必须是合法 IP，否则退化成占位符。

### F2 · IPv6 虚拟接口地址不再判为异常

- 用 `Get-NetIPAddress -AddressFamily IPv6` 取全局 IPv6 的**所属接口名**（Windows 权威），不再只靠 `ipconfig` 文本匹配。
- 判定「虚拟/隧道接口」：接口名或描述命中既有 `_VPN_INTERFACE_KEYWORDS`（ZeroTier / Tailscale / WireGuard / tun / tap 等）或补充的虚拟网卡关键字（vEthernet / Hyper-V / VirtualBox / VMware / Docker / WSL / ISATAP / 隧道）。
- **全局 IPv6 全部来自虚拟接口**时：
  - 结论改为「IPv6 来自虚拟接口（本机无运营商原生 IPv6）」；
  - 状态降为**信息级**（徽章显示「提示」），**不进待办清单**，不参与扣分；
  - 不再单列「IPv6 DNS 解析失败」异常（无原生 IPv6 时它是上一条的必然结果）；
  - 卡片建议写：「如需 IPv6 请联系运营商开通并确认路由器下发前缀；仅使用 VPN/隧道时可忽略本项」。
- **全局 IPv6 来自物理接口**但不可达时，维持现状（异常级 + 联系运营商/检查路由器）。
- 报告系统信息里带出「本机是否有原生 IPv6 路径」的布尔，供渲染层区分。
- **「全球单播」判定用 2000::/3**（`_is_ipv6_global_addr`）：排除 fc00::/7 唯一本地
  （ZeroTier 自带的 fd9f:… 属于此类，不是公网地址）、fe80::/10 链路本地、::1、ff00::/8 组播。
- **徽章换文案但不新增状态值**：`_present_module` 在该场景写 `badge_text="提示"`，
  渲染层用中性蓝 `.hint` 样式 —— 计数 / 评分 / 终端口径全部不变（IPv6 本就是豁免模块）。

### F3 · DNS 指标按当前 DNS 统计 + 建议动态化

- 指标卡「平均响应」改统计**当前系统 DNS**（`system_dns` 列表里的那些服务器）的成功查询平均，各对比服务器仍列为参考。
- 判据：当前 DNS 平均 > 100ms → 警告；> 200ms → 异常。**不再**用混算平均判定。
- 问题文案不再出现混算数字，改为「当前 DNS (223.5.5.5) 平均响应 Xms 较慢」。
- 建议动态化：
  - 当前 DNS 达标且为实测最快 → 「当前 DNS (223.5.5.5) 实测 X ms，本次对比中最快，无需更换」；
  - 当前 DNS 偏慢 → 「当前 DNS X ms 偏慢，建议改用实测最快的 <名称> (<IP>)（Y ms）」并附 `netsh interface ipv4 set dnsservers ...` 命令；
  - **当前 DNS 里混着明显更慢的那台**（实测本机是 223.5.5.5 + 8.8.8.8，后者被限速到 ~147ms）
    → 点名那台：「当前 DNS 里 8.8.8.8 (146.8ms) 明显慢于 AliDNS (223.5.5.5, 6.0ms)」，
    建议只留快的那台，并给出**带真实网卡名**的 `netsh interface ipv4 set dnsservers
    name="以太网" source=static address=223.5.5.5 primary`（网卡名从
    `Get-DnsClientServerAddress` 取，拿不到时退化成 `<接口名>` 占位）；
  - **命令里插值的两个值都要过白名单**：网卡名走 `_safe_iface_name`，
    **DNS 地址走 `_safe_ip_literal`** —— 非法一律退化成占位符
    （`<接口名>` / `<DNS服务器地址>`），不带脏字符进命令。
    （v1.20.0 补齐：原先只校验了网卡名，地址是直接内插的。）
  - 有查询失败/超时 → 单独一条信息项，列出「服务器 · 域名 · 超时」，归因指向该 DNS 限流或 UDP 被拦截。
- 指标卡的提示里给出**当前 DNS 逐台耗时**（如「AliDNS 6.0ms / GoogleDNS 146.8ms」），
  让"平均被谁拖慢的"一眼可见。
- 固定文案「尝试更换 DNS 服务器 (阿里/腾讯/114)」**从代码中移除**，任何场景不得再出现。

### F4 · 扣分明细（B 方案）

- **模块卡标题栏右侧**：
  - 有扣分的模块 → 扣分徽标（如 `−2 分`），配色跟该模块状态色；
  - 评分豁免模块 → 灰色「豁免」标记（说明它的问题不计入总分）；
  - 完成模块 → 不显示任何标记（不刷屏）。
- **hero 评分旁一行算式**：`92 / 100 ＝ 100 − 警告 4×2`；无扣分时写 `100 / 100 ＝ 无扣分项`。
- **不在待办清单里标扣分**。原因：豁免模块的问题也进待办清单（IPv6 异常、代理检测、环回测速），在那里标分数必须额外解释「豁免不扣分」，反而更绕；且待办清单最多 10 条，扣分项可能被截断，与总分对不上。
- 扣分表提为常量 `SCORE_PENALTY = {"异常": 20, "错误": 30, "警告": 2, "超时": 10}`，`compute_health_score` 与报告渲染层共用同一份，权重值不变。

### F5 · 诊断条不再做无依据断言

- 无根因、无未完成模块时：徽章从「✓ 无故障」改为「未匹配到根因」（中性色，不用绿色对勾）；后缀写「N 项问题已列在下方」（N 取待办条数）；**不显示置信度**，**不显示「评估 N 条规则」**。
- 有未完成模块（超时/错误）时：维持现状（「⚠ 未定位到根因」+ 说明）。
- 有根因时：保留置信度与触发规则数（此时置信度有意义）。
- 「评估 N 条规则」如需保留，只放进 `title` 提示，正文不显示。

### F6 · LAN 隐私披露串不再算问题

- OUI 在线补查的披露串从模块 `issues` 列表挪到独立字段 `disclosures`（列表），`determine_status` 不再因它判警告。
- 披露**不能丢**：渲染到模块卡的信息行与本机信息区的第三方服务说明处（v1.15.2 披露 MAC 发给第三方的初衷保留）。

## 不做什么

- 不新增任何 Probe（守 v1.8.1 收口规则）。
- 不改终端诊断汇总框口径（仍只给健康分 + 异常模块数两行）。
- 不改一页版 brief_v2 的版式与高度锁；评分明细只进完整版报告。brief_v2 的问题文案随 `_issues_*` 共享源自动受益，但版式不动。
- 不改评分权重（异常 −20 / 错误 −30 / 警告 −2 / 超时 −10）与豁免模块名单。
- 不改 OUI 在线补查功能本身（仍默认开启，MAC 仍只发 OUI 前缀对应的完整 MAC）。
- 不做原生 IPv6 的扩展探测（不新增 DHCPv6 / IPv6 路由质量探测）。
- 不动出口码与导出 JSON 的既有字段集合（只允许新增）。

## 硬约束

- **单一来源**：扣分表来自 `SCORE_PENALTY`；模块状态配色仍走 `STATUS_KEY` / `STATUS_COLORS`；不在渲染函数里另立映射。
- **不新增 `LAST_RUN` 依赖**：新数据走 `runner → report → renderer`。
- **HTML 转义**：文本节点 `_html_esc(s)`，属性值 `_html_attr(s)`。
- 报告**可离线打开**：不引任何在线资源。
- **性能**：确认探测最多 +3 次 ping（≤6 秒），且只在收敛值贴近标准时触发；收敛值明显偏小时不触发。
- **不放宽到漏报**：真实 PPPoE（路径 MTU 1492，差 8 字节）必须仍然报警并给出修复命令。
- 判据改动后，**豁免模块不得因降级而改变豁免身份**（IPv6 仍是豁免模块）。

## 术语

- **当前 DNS**：系统配置里实际在用的 DNS 服务器（报告顶部 DNS chip 那个）。与「对比服务器」区分。
- **对比服务器**：DNS 诊断里额外测试的公共 DNS（阿里 / 腾讯 / 114 / 百度 / CNNIC），用户未必在用。
- **确认探测**：二分收敛后对标准 MTU 载荷（1472 字节 + DF）追加的 3 次 ICMP 探测。
- **虚拟接口**：Windows 上非物理网卡的适配器（ZeroTier / Tailscale / Wintun / Hyper-V / VirtualBox / WSL / 隧道等）。
- **原生 IPv6**：由运营商下发、绑定在物理接口上的全局 IPv6（区别于虚拟接口上的手工地址）。
- **豁免模块**：不参与健康分扣分但状态照常展示的模块（iperf3 / ipv6 / proxy / nattype / loopback）。
