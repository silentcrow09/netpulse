# 模块勾选高级面板（v1.23.0）· 验收要求

> 唯一依据：`docs/spec.md`。前一特性（盯障实时窗口 v1.22.0）的 spec/verify
> 见 git 历史 `85306fa`。

## 场景级验收（端到端）

### S1 · 入口与面板渲染
- 动作：按定稿入口（选型结论）进面板
- 期望结果：
  1. 面板三分类分组与 `/api/scenarios` 的 `module_catalog` 一致（24 项、
     6/5/13 分布、中文名同源），无页面内嵌清单；
  2. 组操作（组全选/清空、顶部全选/清空/反选）与已选计数正确；
  3. `tcpcc` 项带红字压测警示；`port`/`iperf3` 勾选时展开内联输入；
  4. N=0 时「运行所选」禁用。
- 判定：四条同时成立 = 通过
- 证明方式：实机 + dump-dom 锚点断言 + 截图

### S2 · 组合运行闭环
- 动作：勾「DNS 诊断 + MTU 检测」→ 运行
- 期望结果：
  1. 既有进度页推进，label 显示「模块组合 (2 项)」；
  2. 完成转报告页：模块卡恰好 2 个、徽章与模块状态一致；
  3. 导出 HTML 文件名含「模块组合」；全规则根因评估（报告技术附录
     无场景过滤痕迹即可，不要求必出根因）；
  4. 互斥：运行中 `/api/monitor/start` 与场景卡均 409/禁用。
- 判定：四条同时成立 = 通过
- 证明方式：实机跑 + 导出文件核验

### S3 · port/iperf3 两口径
- 动作/期望：
  1. 仅勾 `port` 留空目标运行 → 报告该模块「警告 · 未提供目标」（与终端
     无目标语义一致）；
  2. 勾 `port` 填非法目标（如 `abc`）→ 400 留在面板报错，不启动；
  3. 勾 `port` 填合法目标（如 `223.5.5.5:53`）→ 报告按目标出结果；
  4. 勾 `iperf3` 留空服务器 → 模块「未检测」（归一化口径）。
- 判定：四条同时成立 = 通过
- 证明方式：实机四轮（短模块，快）+ 报告核验

### S4 · tcpcc 与独占调度
- 动作/期望：
  1. 勾 `tcpcc` 运行 → confirm 弹出；确认后运行（压测语义与终端单独选中
     一致；轮次可随时停止不要求——诊断无停止，等它跑完或用小 max 观察即可
     ——**简化：confirm 后立即断言请求发出即可，不必等 4000 连接跑完**，
     用 `--tcpcc-max` 等价的小配置无 GUI 入口，故此条只验「确认后发出请求」）；
  2. 勾「测速 + 网页体检」运行 → 测速串行独占（进度页顺序可证），
     结果与终端单独跑同口径；
  3. 勾全部 24 项 = 与「完整诊断」同集合（含 tcpcc），行为一致。
- 判定：三条同时成立 = 通过
- 证明方式：实机 + 进度轨迹留证

### S5 · Ookla 对照开关
- 动作/期望：勾 `speedtest` 显示开关；关（默认）运行 → 报告无 Ookla 对照块；
  开 → 运行时间明显变长且报告含 Ookla 官方测速对照（或其失败说明）。
- 判定：两条同时成立 = 通过
- 证明方式：实机两轮对照

### S6 · 服务端校验与互斥
- 动作/期望：
  1. `keys` 含非法 key / 空数组 / 与 `profile` 同时出现 → 400；
  2. 诊断或盯障进行中 → 面板运行 409；反向：面板运行中其它入口 409/禁用；
  3. 无 token → 403。
- 判定：三条同时成立 = 通过
- 证明方式：API 实测

### S7 · 终端与既有回归
- 动作/期望：
  1. 终端菜单 `9` → 模块菜单交互（多选/分类字母/序号/0）与 v1.22.0 一致；
  2. `--list` 输出不变；
  3. 既有 GUI 七卡 + 场景/现场/盯障全流程抽测正常；
  4. 全量 pytest 绿（现有用例零改动）。
- 判定：四条同时成立 = 通过
- 证明方式：实机逐条 + pytest 输出

### S8 · 视觉验收
- 动作：面板页与设计稿定稿（含入口选型结论）并排比对
- 期望结果：布局/层级一致、字号真实、恶意 key/目标输入不破版
  （textContent 路径）、零外链、状态色同源。
- 判定：四条同时成立 = 通过
- 证明方式：逐页截图人工核对 + 恶意串实测

## 判定口径

- 「与终端语义一致」= 同一输入下模块结果/状态/归一化口径相同
  （对比基准 v1.22.0 实测），不要求界面文案逐字相同。
- S4.1 以「确认后请求发出」为闸，不以压测跑完为闸（压测完整行为已有
  终端既有语义背书）。
- 组合报告的根因评估不设「必出根因」断言（全规则评估是口径，不是结果承诺）。
