# 本地 GUI 壳（v1.21.0）· 验收要求

> 唯一依据：`docs/spec.md`。本文件只规定「验什么、怎样判定」，不规定「怎么实现」。
> 实现与测试代码不在本文件范围内；执行与结果由交付阶段负责。
>
> 前一特性（报告判级纠偏 v1.20.0）的 spec/verify 见 git 历史 `41637ef`。

## 场景级验收（端到端）

### S1 · 双击入口：应用窗口弹出
- 前提：本机装有 Edge 或 Chrome（Chromium 探测链可用）
- 动作：TTY 下无参数启动（双击 exe / `py netpulse.py`）
- 期望结果：
  1. 弹出**独立应用窗口**（`--app` 模式，无地址栏无标签页），主页可见 6 张场景卡 +
     「完整诊断」次级按钮；
  2. 终端侧无诊断内容输出；HTTP 服务只监听 `127.0.0.1`；
  3. URL 带 token，页面正常加载；
  4. 双击 exe（独立 conhost）场景下宿主黑框自动隐藏；从已有终端 `py netpulse.py` 启动
     时该终端保持可见不被隐藏。
- 判定：四条同时成立 = 通过
- 证明方式：实机跑 + 截图 + `netstat -ano` 查监听地址

### S2 · 场景诊断闭环：点卡片 → 进度 → 报告内嵌
- 前提：S1 的窗口已打开
- 动作：点「网络很慢」场景卡
- 期望结果：
  1. 进入进度页：模块逐个亮灯，完成计数最终 = 实跑模块数（`DIAGNOSE_PROFILES["slow"]`
     的键数）；每个模块的亮灯状态与导出报告中该模块徽章一致；
  2. 进行中模块显示一句人话说明；进度页只显示已耗时，不出现 ETA；
  3. 完成后自动进入报告页：健康分/等级/一句话结论可见；
  4. 内嵌报告与「存 HTML」导出的文件为同一次 `build_report` 产物的同一渲染
     （内嵌页与导出文件的核心区块字面一致）；
  5. 诊断进行中回到主页：场景卡禁用 + 状态条可回到进度页（单轮互斥生效）。
- 判定：五条同时成立 = 通过；进度计数与报告不一致 = 不通过
- 证明方式：实机跑 + 内嵌页与导出文件 diff 核对

### S3 · 报告导出四件
- 前提：S2 已完成一轮诊断，本机有 Chrome 或 Edge
- 动作：依次点「存 HTML」「导出 PDF」「存 JSON」「打开报告文件夹」
- 期望结果：
  1. HTML/JSON 落盘 `桌面\NetPulse\`，文件名含时间戳；HTML 可独立打开且内容与内嵌页一致；
  2. PDF 在同目录生成，可打开；文件名与 HTML 同基名；
  3. 「打开报告文件夹」弹出资源管理器定位到该目录；
  4. 无 Chromium 环境（模拟）时：PDF 按钮禁用并注明原因，其余三件不受影响。
- 判定：1–3 全部成立 + 4 成立 = 通过
- 证明方式：实机跑 + 文件存在性检查 + 无 Chromium 场景模拟（临时改探测函数返回 None）

### S4 · 现场检测端到端
- 前提：GUI 主页可见，本机有 Chrome 或 Edge
- 动作：点「现场检测」→ 填客户名「张伟·幸福小区3-502」、签约带宽 300M → 开始 →
  等诊断完成 → 机房 6 项勾选（至少一项选「异常」、其余留「未查」）+ 填备注 → 产出
- 期望结果：
  1. 客户名留空时「开始」按钮不可用（必填生效）；
  2. 诊断模块集排除 `port` 与 `iperf3`，且不含 tcpcc 压测（与终端 `--site` 同口径）；
  3. 机房 6 项每项按 `SITE_CHECK_ITEMS` 的 options 单选（默认未检）；未检项按
     「未检查」进报告（不丢项）；选中 `bad` 清单内选项的项给出建议文案（与终端一致）；
  4. 产出四件套（一页版 brief_v2 HTML / 完整版 HTML / JSON / PDF），文件名含消毒后的
     客户名，落在报告目录；PDF 打开为一页客户报告样式；
  5. 报告含签约带宽达标格（实测/签约 ≥90% 判达标）与现场备注。
- 判定：五条同时成立 = 通过
- 证明方式：实机跑 + 四件套逐一打开核对 + 与一次终端 `--site` 产出做结构对比

### S5 · 终端模式完整保留
- 动作/期望：
  1. `--cli` → 进入旧交互菜单，场景/高级/现场入口与 v1.20.0 一致；
  2. `--json --diagnose slow`（或等价组合）→ stdout 为纯 JSON，无 ANSI/框线污染；
  3. 管道下无参数启动 → 不弹窗口、不启 HTTP 服务，行为与现状一致；
  4. `--diagnose` 之外的既有参数（`--site`/`--monitor`/`--list`/模块位置参数）各自行为
     与 v1.20.0 一致（抽测 3 项以上）；
  5. 全量 pytest 套件绿（用例零改动）。
- 判定：五条全部成立 = 通过
- 证明方式：实机逐条跑 + pytest 输出

### S6 · 浏览器降级链
- 动作/期望（三种环境各验一次，可用临时改探测函数的方式模拟）：
  1. 有 Chromium：`--app` 独立窗口；
  2. 探测失败但系统有默认浏览器：`webbrowser.open()` 拉起普通标签页加载同一 URL，
     功能完整（进度/报告/导出全部可用）；
  3. 全无浏览器：终端打印带 token 的完整 URL 与说明，进程驻留；手动用任意浏览器打开
     该 URL 功能完整。
- 判定：三级降级各按期望成立
- 证明方式：模拟探测失败 + 实机跑

### S7 · 环回隔离与 token
- 前提：GUI 已启动（从窗口 URL 或终端提示取得端口）
- 动作/期望：
  1. `netstat` 显示监听地址为 `127.0.0.1`（非 `0.0.0.0`）；
  2. 无 token 直接请求任一 API/页面（`curl http://127.0.0.1:<port>/api/...`）→ 被拒绝
     （非 200 且不含报告内容）；带正确 token → 正常；
  3. token 每次启动重新生成（重启后旧 URL 失效）。
- 判定：三条同时成立 = 通过
- 证明方式：curl 实测 + 两次启动对比

### S8 · 窗口生命周期
- 动作/期望：
  1. 空闲时关闭窗口 → 进程退出（无残留监听进程）；
  2. 诊断进行中关闭窗口 → 出现确认提示（文案含「诊断仍在进行」），确认后进程退出；
  3. 强杀浏览器进程（不走 unload）后再次启动 → 正常（新端口新 token），旧进程不阻塞新实例。
- 判定：三条同时成立 = 通过
- 证明方式：实机跑 + 任务管理器/netstat 复核

### S9 · 收口红线核查
- 动作：对本特性新增代码做 diff 审查 + 跑全量测试
- 期望结果：
  1. 新增代码无任何 `LAST_RUN` 直接读写（现有引用只减不增）；
  2. 新增代码无新增 Probe；无新增状态值；未另立状态色映射（状态色只引用
     `STATUS_COLORS`/`STATUS_KEY`）；
  3. 页面模板中一切动态插值点均经 `_html_esc`/`_html_attr`；
  4. 全量 pytest 绿。
- 判定：四条同时成立 = 通过
- 证明方式：diff 逐条人工核对（按 AGENTS.md 判定口径）+ 测试输出

### S10 · 视觉验收（逐页人眼核对）
- 前提：对照 `design_ref/gui/gui_design_v1.html` 定稿版（含 Simon 选型结论）
- 动作：GUI 五个界面（主页 / 进度页 / 报告页 / 现场检测四步）逐页与设计稿并排比对
- 期望结果：
  1. 布局结构、信息层级与定稿设计稿一致；字号为真实渲染字号；
  2. 状态语义色正确：超时=中性灰、警告橙、异常红（与 `STATUS_COLORS` 对齐）；
  3. 转义抽查：主机名/客户名插值点构造恶意串（如 `<img src=x onerror=alert(1)>`），
     页面中以转义形式出现，不执行、不破版；
  4. 全部页面零外链资源（断网可用）。
- 判定：四条同时成立 = 通过
- 证明方式：逐页渲染截图人工核对（脚本闸全绿不等于可交付）+ 恶意串用例实测

## 判定口径

- 「行为与现状一致」的比对基准 = v1.20.0（`41637ef`）的实测行为，不是文档描述。
- S2/S4 中「口径一致」一律以**同一 report dict 的产物对比**为准（内嵌 vs 导出文件），
  不做两次独立跑的数值对比（网络诊断两次跑数值本就不同）。
- 涉及 HTML 的断言不得写「整页无 `<script>`」（报告自带合法 JS）；判据为：
  改前/改后 `<script>` 数量一致 + 注入恶意串不以原始形式出现。
- 进度页模块计数断言必须对齐**实际选中模块集**（场景=DIAGNOSE_PROFILES 子集；
  现场检测=全量减 port/iperf3），不得拿全口径硬套场景。
