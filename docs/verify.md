# 控制台界面现代化（方案 B）· 验收要求

> 唯一依据：`docs/spec.md`。本文件只规定「验什么、怎样判定」，不规定「怎么实现」。
> 实现与测试代码不在本文件范围内；执行与结果由交付阶段负责。

## 批次 1

### S1 · VT 不可用时不出现乱码

- 前提：mock `ctypes.windll.kernel32`，`GetConsoleMode` 失败 / `SetConsoleMode` 拒绝
  VT 标志两种失败形态各测一次
- 动作：调用 `_cli_enable_vt()` 后经 `_c()` 输出带色文本
- 期望结果：
  - `_cli_enable_vt()` 返回 False，且 `_C_NOCOLOR` 被置 True
  - 输出文本中不含任何 `ESC [` 转义序列字节（`\x1b[`）
- 判定：通过 / 不通过
- 证明方式：单测（mock 两种失败形态）+ 机械检查

### S2 · VT 可用时颜色不受影响

- 前提：mock kernel32 两个调用都成功
- 动作：同 S1
- 期望结果：
  - `_cli_enable_vt()` 返回 True，`_C_NOCOLOR` 保持 False
  - 输出文本含 ANSI 颜色码（与修复前一致，不因修复变灰）
- 判定：通过 / 不通过
- 证明方式：单测（mock 成功形态）

### S3 · 终端状态色板覆盖且语义对齐

- 动作：检查 `STATUS_STYLE`
- 期望结果：
  - 键集合覆盖 `STATUS_BAR_ORDER` 全部 6 个状态
  - 「超时」= 灰（不再是红）；「异常」「错误」= 红；「完成」「正常」= 绿；「警告」= 黄
  - `_cli_status_badge` 对每个状态键输出的行，`_disp_width` 等于 `[状态]` 的显示宽度（ANSI 不计）
- 判定：通过 / 不通过
- 证明方式：单测（断言映射）+ 机械检查

### S4 · 既有行为零回归（批次 1）

- 动作：跑全量测试套件
- 期望结果：全绿；特别是 `test_log_report.py`（72 用例）、`test_console_encoding.py`、
  盯障 VT 相关用例（`test_v1150_backlog.py`）不红
- 判定：通过 / 不通过
- 证明方式：测试报告

## 批次 2

### S5 · 首页横幅与菜单

- 前提：TTY 下运行 `NetPulse.exe`（无参数）
- 动作：目测首页 + 渲染函数落盘
- 期望结果：
  - 横幅为闭环框（上下横线接右角），权限徽标为灰字
  - 菜单双分区 + 卡片条 + 说明副行；各列起点按显示宽度对齐（同一列号的行首位置一致）
  - mock 终端宽度 60 列时说明列收起，无折行错乱
  - 菜单编号 [1]-[9]/[A]/[C]/[0] 语义与选择行为与改造前一致
- 判定：通过 / 不通过
- 证明方式：单测（落盘比对 + 宽度断言）+ 场景验证（人眼）

### S6 · 诊断进度

- 前提：VT 可用跑一次多模块诊断
- 动作：观察进度画面；再 mock VT 不可用跑一次
- 期望结果：
  - VT 可用：进度条单行刷新、结束后无残留字符；每模块一行，状态符号与
    实际结果一一对应（完成✓绿/警告⚠黄/错误✗红/进行中…灰）
  - VT 不可用：回退静态两列列表，内容与现状一致，无乱码
  - 模块组合、串行口径与改造前一致（对照 `LAST_RUN` keys）
- 判定：通过 / 不通过
- 证明方式：单测（两种形态 + mock 进度回调）+ 场景验证（人眼）

### S7 · 完成屏

- 前提：跑完一次场景诊断
- 动作：检查完成屏
- 期望结果：
  - 健康分数字 = `report["health"]["score"]`，等级徽章色随等级
  - 状态分布条各段数字按 `report["summary"]`（全口径）计数 —— 与 HTML 状态
    分布条同口径；豁免模块名单在框内注明
  - 按 [H] 打开报告文件（调用打开动作恰一次、目标路径即打印的路径）；[Enter] 回菜单
  - 报告内容与导出文件不受影响（渲染器零改动）
- 判定：通过 / 不通过
- 证明方式：单测（数值同源断言 + mock 打开动作）+ 场景验证（人眼）

### S8 · 提示框与提示符统一

- 动作：触发 scapy 缺失框、异常上报告知框、抓包授权框
- 期望结果：
  - 三个框均闭环（右侧竖线/右角齐全），内容行显示宽度 = 框内宽
  - 所有 input 提示以「» 」结尾；[Y/N] 选项绿/红着色
  - 确认行为（Y/N/回车默认）与改造前一致
- 判定：通过 / 不通过
- 证明方式：单测（复用 `test_notice_box_encloses_text` 的等宽断言模式）+ 机械检查（grep 提示符）

### S9 · 机器可读输出零回归（批次 2）

- 动作：`NetPulse.exe --json <modules>` 管道执行；`--no-color` 执行
- 期望结果：
  - stdout 为纯 JSON（`json.loads` 一次通过），不含 ANSI 码
  - `--no-color` 下终端输出无转义序列
  - 全量测试套件全绿
- 判定：通过 / 不通过
- 证明方式：测试报告 + 机械检查
