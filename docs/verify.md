# GUI 首页紧凑化 + 场景合并（v1.26.0）· 验收要求

> 唯一依据：`docs/spec.md`。本文件只规定「验什么、怎样判定」，不规定「怎么实现」。
> 实现与测试代码不在本文件范围内；执行与结果由交付阶段负责。

## 场景级验收（端到端）

### S1 · 主页 6 卡 3×2 对称
- 前提：GUI 启动，`/api/scenarios` 正常返回
- 期望结果：
  1. `scenarios` 恰 6 项，顺序 `web, disconnect, gaming, wifi, site, monitor`；
  2. 页面 `#cards` 渲染 6 张卡，网格 3 列 2 行（第三行无孤行）；
  3. 第一张卡标题「网页打开慢」；无「网络很慢」「网页打不开」卡片。
- 判定：1–3 全部满足 → 通过
- 证明方式：机械检查（测试断言）+ 人眼核对渲染页

### S2 · 主页一屏（含横幅压力场景）
- 期望结果：视口 **1180×720** 下，主页整页 `scrollHeight ≤ 720`（无滚动条）；
  人为使续跑横幅可见（注入一条未完成续跑点）后再次测量，仍 `≤ 720`。
- 判定：两种状态均 ≤720 → 通过
- 证明方式：机械检查（无头浏览器量几何，1180×720 视口）

### S3 · 合并场景执行口径
- 期望结果：
  1. `SCENE_LABELS["web"] == "网页打开慢"`；`"slow"` 不在 `SCENE_LABELS` /
     `DIAGNOSE_PROFILES`；
  2. `DIAGNOSE_PROFILES["web"]` 为 11 项并集（gateway/external/dns/wifi/web/
     tcp/tcpstats/mtu/route/speedtest/bufferbloat）；
  3. `PROFILE_RULES["web"]` 为 7 条并集（含 `wifi_weak` 与 `wan_interruption`、
     `mtu_blackhole`）；
  4. `POST /api/run {"profile":"slow"}` 被拒绝（非 200 / ok=false）；
     `{"profile":"web"}` 正常受理并进入进度页。
- 判定：1–4 全部满足 → 通过
- 证明方式：机械检查（单元 + 路由契约测试）

### S4 · 终端菜单同步
- 期望结果：
  1. 场景区 4 行：`1 网页打开慢 / 2 经常断网 / 3 游戏卡顿 / 4 WiFi 信号差`；
  2. 工具区键位 `5 现场检测 / 6 持续盯障 / 7 高级选项 / A 管理员模式`；
     键 `8`、`9` 不再是有效场景/工具入口（按既有无效键处理）；
  3. 键位分派正确：`1` 启动 web 场景（11 模块集），`5` 进现场检测，`6` 进盯障，
     `7` 进高级菜单，`A` 进管理员模式；
  4. 场景副行文案与 11 项模块集一致，不出现已删模块的能力承诺。
- 判定：1–4 全部满足 → 通过
- 证明方式：机械检查（菜单渲染/分派测试）+ 人眼核对

### S5 · 卡片规模副行
- 期望结果：场景卡副行显示模块规模（web 卡「11 项模块」类文案，数值取自下发
  `modules` 字段）；site/monitor 卡按设计稿给等价规模提示；全页不再出现
  7 处重复的「点击开始 →」；耗时预告句本次不出现（spec 范围 §2 明确不实现）。
- 判定：满足 → 通过
- 证明方式：机械检查（DOM 断言）+ 人眼核对

### S6 · 窗口默认尺寸
- 期望结果：`_gui_launch_browser` 的 Chromium app 分支传 `--window-size=1180,720`；
  降级链（默认浏览器 / none）行为不变。
- 判定：满足 → 通过
- 证明方式：机械检查（单元测试）

### S7 · 现场检测页版式对齐
- 期望结果：步骤条与表单所在限宽盒（720→760px）整体**水平居中**（现状靠左），
  盒内元素相对关系不变；页高在 720 窗口内无滚动（现状 512px + 新顶栏，余量充足）。
- 判定：满足 → 通过
- 证明方式：机械检查（几何断言）+ 人眼核对

### S8 · 旧续跑点兼容
- 前提：`resume.json` 为 `profile:"slow"` 的历史点（手工构造）
- 期望结果：主页横幅正常显示不崩溃；label 不出现英文 id `slow`（退化通用文案）；
  「接着跑」按 keys 执行不受影响。
- 判定：满足 → 通过
- 证明方式：机械检查（构造 fixture 的单元/页面测试）

### S9 · 回归安全网
- 期望结果：
  1. 全仓测试套件绿（含受影响的 slow 引用替换、GUI 卡片数/文案断言、菜单键位
     断言更新）；
  2. 导出链 golden 基线逐字节不变（`tests/test_report_golden.py` 不 bless）；
  3. GUI 资产闸延续：无 `<iframe>`、textContent 规则、页面不内嵌模块清单/色表；
  4. 报告页/进度页/盯障三视图渲染不回归（口径与结构零变化）。
- 判定：1–4 全部满足 → 通过
- 证明方式：机械检查（既有测试套件）
