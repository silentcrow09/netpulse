# 报告判级纠偏与扣分明细（v1.20.0）· 验收要求

> 唯一依据：`docs/spec.md`。本文件只规定「验什么、怎样判定」，不规定「怎么实现」。
> 实现与测试代码不在本文件范围内；执行与结果由交付阶段负责。
>
> 前一特性（控制台界面现代化）的 spec/verify 见 git 历史 `f9fa484`。

## 场景级验收（端到端）

### S1 · 真实 MTU=1500 的链路不再报分片风险
- 前提：本机到 223.5.5.5 的路径 MTU = 1500（已实测：`ping -f -l 1472` 5/5 通，`-l 1473` 3/3 需拆分）
- 动作：跑一次含 `mtu` 模块的诊断，导出 HTML 报告
- 期望结果：待办清单**没有**「路径 MTU … 小于标准 1500」；MTU 模块徽章不是警告；技术细节里该目标的 `path_mtu` = 1500
- 判定：通过 = 上述三条同时成立；不通过 = 任一条不成立
- 证明方式：场景验证（实机跑 + 渲染结果人工核对）

### S2 · 真实 PPPoE（路径 MTU 1492）仍然报警并给出可执行命令
- 前提：构造 fixture —— 路径 MTU 1492、确认探测 3 次全失败、出口接口名已知
- 动作：用该 fixture 渲染 HTML 报告
- 期望结果：出现「路径 MTU (1492) 小于标准 1500」警告级问题；该问题的建议里**同时**出现核实命令 `ping -f -l 1472 -n 5`、修复命令 `netsh interface ipv4 set subinterface` 且 mtu 值 = 1492、复查命令 `netsh interface ipv4 show subinterfaces`
- 判定：通过 = 三段命令字符串均在建议文本内；不通过 = 缺任一段，或 mtu 值与实测路径 MTU 不一致
- 证明方式：场景验证（fixture 渲染 + 文本断言）

### S3 · IPv6 只来自虚拟接口 → 提示级，不进待办
- 前提：构造 fixture —— 全局 IPv6 `2a01:…` 绑定在 ZeroTier 虚拟接口、无 `::/0` 路由、IPv6 连通性失败
- 动作：渲染 HTML 报告
- 期望结果：IPv6 模块徽章显示「提示」；**待办清单里没有** IPv6 相关条目；模块卡结论含「虚拟接口」字样；不出现单独的「IPv6 DNS 解析失败」异常条目；建议文案含「如需 IPv6 请联系运营商开通」的条件句式
- 判定：通过 = 上述五条同时成立；不通过 = 任一条不成立
- 证明方式：场景验证（fixture 渲染 + 人工核对）

### S4 · 顶栏 IPv6 地址标注为出口地址
- 前提：沿用 S3 的 fixture，且第三方服务回报了一个公网 IPv6
- 动作：渲染 HTML 报告
- 期望结果：顶栏 IPv6 chip 文案含「出口」；其 `title` 提示含「非本机原生 IPv6」；chip 仍存在（不被删除）
- 判定：通过 = 文案与提示同时成立；不通过 = 文案仍是裸「IPv6 <地址>」或 chip 消失
- 证明方式：场景验证（fixture 渲染 + 文本断言）

### S5 · DNS 指标按当前 DNS 统计，不建议换 DNS
- 前提：构造 fixture —— 当前 DNS 223.5.5.5 平均 5.8ms（4/4 成功），5 台对比服务器平均 30~300ms
- 动作：渲染 HTML 报告
- 期望结果：指标卡「平均响应」显示的是**当前 DNS** 的 5.8ms（不是混算值）；模块不产生「DNS 较慢」警告；建议文案为「当前 DNS … 最快，无需更换」类；**全文不出现**「尝试更换 DNS 服务器 (阿里/腾讯/114)」
- 判定：通过 = 上述四条同时成立；不通过 = 任一条不成立
- 证明方式：场景验证（fixture 渲染 + 文本断言）

### S6 · 当前 DNS 真慢时，建议改到实测最快的那台
- 前提：构造 fixture —— 当前 DNS 平均 300ms；实测最快为 DNSPod 119.29.29.29（11ms）
- 动作：渲染 HTML 报告
- 期望结果：产生警告级问题「当前 DNS … 较慢」；建议点名 `119.29.29.29` 并附 `netsh interface ipv4 set dnsservers` 命令；**不出现**固定文案「(阿里/腾讯/114)」
- 判定：通过 = 点名 + 命令 + 无固定文案三条同时成立
- 证明方式：场景验证（fixture 渲染 + 文本断言）

### S7 · 扣分明细可见且与总分对得上
- 前提：构造 fixture —— 4 个警告模块（LAN / DNS / TCP 传输质量 / MTU）+ 1 个豁免模块带问题 + 若干完成模块
- 动作：渲染 HTML 报告
- 期望结果：
  1. 4 个扣分模块的卡片标题栏右侧各有一个扣分标记，数值与该模块状态对应（警告 −2 / 异常 −20 / 错误 −30 / 超时 −10）；
  2. hero 评分旁有一行算式，能从数字推出总分（如 `92 / 100 ＝ 100 − 警告 4×2`）；
  3. 豁免模块标题栏右侧显示灰色「豁免」标记，且**不显示**扣分数字；
  4. 完成模块标题栏右侧**没有任何**标记；
  5. 待办清单条目上**不出现**扣分数字。
- 判定：通过 = 五条同时成立；不通过 = 任一条不成立
- 证明方式：场景验证（fixture 渲染 + 人工核对）

### S8 · 无根因时不再断言「无故障」
- 前提：构造 fixture —— `rules_fired = 0`、有 4 条警告待办、无超时/错误模块
- 动作：渲染 HTML 报告
- 期望结果：诊断条**不含**「无故障」；**不含**「高置信度」；**不含**「评估 N 条规则」；含「未匹配到根因」；并说明问题数指向下方待办
- 判定：通过 = 四个「不含」+ 一个「含」同时成立；不通过 = 任一条不成立
- 证明方式：场景验证（fixture 渲染 + 文本断言）

### S9 · LAN 隐私披露串不再算问题
- 前提：构造 fixture —— LAN 结果含 OUI 在线补查披露串、6 台设备厂商均可识别
- 动作：渲染 HTML 报告
- 期望结果：LAN 模块徽章为「完成」；待办清单无 LAN 条目；披露信息**仍然可见**（模块卡信息行或本机信息区），内容含实际补查域名
- 判定：通过 = 徽章 + 无待办 + 披露可见三条同时成立；不通过 = 任一条不成立
- 证明方式：场景验证（fixture 渲染 + 人工核对）

### S10 · 实机全量重跑，结论与实测一致
- 前提：本机环境（路径 MTU 1500、IPv6 仅虚拟接口、当前 DNS 为 AliDNS）
- 动作：跑一次全量诊断并导出 HTML 报告
- 期望结果：待办清单里不再出现「路径 MTU … 小于标准 1500」「有 IPv6 地址但当前无法通过 IPv6 上外网」「DNS 平均响应 … 较慢」三条；顶栏 IPv6 带出口标注；模块标题栏有扣分标记与「豁免」标记
- 判定：通过 = 三条不再出现 + 两个标记可见；不通过 = 任一条不成立
- 证明方式：场景验证（实机跑 + 人工核对报告）

### 判定口径（复检时按这个来，别踩同样的坑）

这几条是 2026-11-12 独立验证时踩过的坑，写下来免得下次又判错：

- **M2 的白名单要含 CSS 选择器**。新增样式（`.badge.hint` / `details.mod>summary .dt*`）
  与诊断条文案不含「MTU/DNS/IPv6」等关键词，按关键词过滤会被误判成「白名单外差异」。
  正确做法：差异行**逐条人工归类**到 6 个改动点（MTU / DNS / IPv6 / LAN / 诊断条 /
  评分区 / 本机信息区），而不是靠关键词命中。
- **M3 的 fixture 必须自洽**。用「模块状态=警告、但卡片里没有警告级问题」的
  矛盾 fixture（比如 DNS 状态写警告、而当前 DNS 实测达标），纠正误报后 findings
  自然少一条 —— 那是**内容修正**，不是版式改动。正确判据是**版式骨架**：
  标签序列一致、行数一致、表头/表格行数一致、`@page` 与 `height: 296mm` 保留。
  用「DNS 真慢」的自洽 fixture，brief_v2 应当只改 2 行文案（findings 标题 +
  模块表行），标签序列与行数完全不变。
- **M6 不能断言整页没有 `<script>`**。报告本身带合法的 `<script>` 块（折叠/复制
  链接），该断言必然失败。正确判据：改前/改后 `<script>` 数量一致 + 注入的恶意串
  **不以原始形式出现**（以 `&lt;script&gt;` 出现）。
- **正则要跟实际引号风格一致**。模块卡是 `id="mod-x"`（双引号），不是
  `id='mod-x'`；顶栏 chip 文本里内嵌 `<b>`，正则不能假设 chip 内没有标签。

## 非目标（回归范围）

- 终端诊断汇总框仍只给「健康分 + 异常模块数」两行，不加明细。
- 健康分权重不变：异常 −20 / 错误 −30 / 警告 −2 / 超时 −10。
- 豁免模块名单不变：iperf3 / ipv6 / proxy / nattype / loopback。
- 一页版 brief_v2 版式与一页高度锁不变。
- OUI 在线补查默认仍开启，MAC 披露行为不变（仍只发实际查询的那台设备的 MAC）。
- 报告仍可离线打开，不引任何在线资源。
- 导出 JSON 的既有字段一个不少（只允许新增）。
- `--json` 输出与改动前结构一致。
- 诊断规则集（8 条根因规则）本身不增不减。
