# 诊断中途取消 / 续跑（v1.24.0）· 验收要求

> 唯一依据：`docs/spec.md`。前一特性（模块勾选高级面板 v1.23.0）的 spec/verify
> 见 git 历史 `c0f0e72`。

## 场景级验收（端到端）

### S1 · 停止（软取消）
- 动作：主页点「网络很慢」→ 进度页点「停止」→ 确认
- 期望结果：
  1. 停止前进度页右上可见「停止」按钮；点击弹确认框（文案含「已完成的项目会保留」）；
  2. 确认后按钮变「正在收尾…」并禁用，页面出现「已停止调度，等当前项目跑完就出
     报告」类提示；
  3. 收尾期间：现场检测 / 盯障 / 新诊断三个入口均 409；
  4. 手头那项跑完后**自动出报告**，不等剩余项（实测：停止后到出报告的耗时应明显
     小于整轮耗时）；
  5. 报告首屏出现「检测范围 N/M 项」（N < M）并注明「本轮提前结束」；
  6. 没跑到的模块显示「未检测」，且**不扣分**（未检测扣 0 分）；
  7. 部分报告可导出 HTML / PDF / JSON 三种。
- 判定：七条同时成立 = 通过
- 证明方式：实机 + API 实测 + 导出文件核验

### S2 · 续跑（同一窗口内）
- 动作：停止后点「继续跑剩下的 N 项」
- 期望结果：
  1. 只跑剩余模块（进度页网格仍显示全部 M 项，已测的保持原状态色，没测的走进度）；
  2. 合并报告覆盖 M/M，模块卡 M 个；
  3. 复用模块的关键指标与第一次运行**逐项一致**（不重测即不应变）；
  4. 报告里能查到「续跑」说明与上次运行时间；
  5. 导出文件名含「（续跑）」；
  6. 续跑点文件已删除（再开程序无横幅）。
- 判定：六条同时成立 = 通过
- 证明方式：实机两轮 + 报告逐项比对 + 导出文件名核验

### S3 · 跨重启续跑
- 动作：停止 → 关窗 → 重开 NetPulse
- 期望结果：
  1. 主页顶部出现续跑横幅，含场景名、实检项数、上次运行时间；
  2. 点「接着跑」→ 只跑剩余模块 → 出完整报告；
  3. 点「重新开始」→ 横幅消失，续跑点文件被删除；
  4. **诊断进行中关窗** → 已完成部分已落盘（在跑的那项算没测完，下次重跑）；
  5. 续跑点文件时间戳超过 7 天 → 自动清理，不提示；
  6. **收尾中（stopping）关窗** → 同样落盘并退出（不能因「还在跑」被 409 卡住，
     否则程序在后台常驻、成果白测）。
- 判定：六条同时成立 = 通过
- 证明方式：实机两轮（关窗 / 重开）+ 文件系统核验

### S4 · 续跑点健壮性
- 动作：人为破坏续跑点（非法 JSON / 缺字段 / 模块结果不是 dict / 目录只读）
- 期望结果：
  1. 非法内容 → 不崩溃，当作没有续跑点，页面不提示；
  2. 落盘失败 → 提示「续跑点保存失败」，当轮报告与导出照常；
  3. 续跑点里某个模块的结果不是 dict → 该模块视为没测完，续跑时**重跑它**，
     不把坏数据带进报告。
  4. 一项都没测完就停止 → **不给**「继续跑」入口（磁盘上没有可续的点，给了点了
     只会报错），并说清「还没测出任何结果」。
  5. 停止请求落在最后一个模块之后（其实全测完了）→ 不给「继续跑剩下的 0 项」
     这种死入口，也不写续跑点（主页横幅不该出现「没跑完 · 实测 N/N 项」）。
  6. **关窗落盘时那一轮已经全测完**（最后一个模块刚测完、报告还没建好就关窗）→
     同样不写续跑点；磁盘上已经存在一个「全测完」的旧点时，读它按「没有可续的」
     处理 —— 主页横幅不出现、点「接着跑」照实说续不了，不把人送进空进度页。
     **读点这一路不删文件**（读路径带删除副作用，可能误删并发写的新点）—— 该点
     在下一次落盘时被覆盖，或 7 天过期自动清理。
  7. **停止路径与关窗路径处置一致**：一轮全测完时，普通新一轮**保留**磁盘上的旧
     续跑点（不抹掉上一轮已测完的成果），续跑轮次**删掉**来源点。
  8. **两条落盘路径并发**（点「停止」后立刻关窗：worker 收尾线程与关窗信标线程
     同时写）→ 续跑点仍是**合法 JSON**，读回不丢成果（不出现「续跑点读取失败,
     已忽略」）。
- 判定：八条同时成立 = 通过
- 证明方式：文件改写 + API 实测

### S5 · 终端零变化
- 动作/期望：
  1. `py netpulse.py --diagnose wifi` 的 stdout 与 v1.23.0 **逐字节一致**；
  2. `--json` 输出可 `json.loads`，字段集不变；
  3. 终端菜单与退出码不变；
  4. 源码层：`run_diagnostics` 的 `cancel_evt` 默认 `None`，终端调用点不传该参数。
- 判定：四条同时成立 = 通过
- 证明方式：改前改后 stdout 逐字节 diff + 源码 grep + pytest

### S6 · 互斥与并发
- 动作：诊断进行中（含「正在收尾」阶段）分别触发盯障 / 现场检测 / 新诊断
- 期望结果：三者均 409；停止收尾结束后互斥解除，可正常发起新一轮。
- 判定：= 通过
- 证明方式：API 实测

### S7 · 报告渲染零回归
- 动作：用固定 LAST_RUN fixture 渲染 customer / brief / brief_v2 三份 HTML
- 期望结果：
  1. 与 v1.23.0 产出**逐行一致**（`Compare-Object` 无差异）；
  2. `tests/test_schema_export_consistency.py` 绿（新增 `note` 字段时 schema 与
     导出同步改齐）；
  3. 全量 pytest 绿。
- 判定：三条同时成立 = 通过
- 证明方式：脚本闸（渲染前后 diff）+ pytest

### S8 · 页面闸与文案
- 期望结果：
  1. 零外链（无 http(s):// 资源引用）；
  2. 页面动态数据一律 `textContent`，新增文案无 `innerHTML` 插值；
  3. 无占位符文案（「待补充」「TODO」「xxx」等）；
  4. 新增中文文案无病句、无 IT 黑话（装维大白话）。
- 判定：四条同时成立 = 通过
- 证明方式：`tests/test_gui_page.py` + 人眼逐条读文案

### S9 · 现场检测降级
- 动作：现场检测的诊断阶段点「停止」
- 期望结果：
  1. 可停止并出部分报告（可导出）；
  2. 页面明确说明「现场检测不支持续跑，请重新检测」，不出现「继续跑」入口；
  3. 停止后互斥解除，可重新发起现场检测；
  4. **停得太早**（一项都没测完就点停止）→ 相位=cancelled 并给出同款说明，
     **不能**把 `RuntimeError: 诊断未产生数据` 抛给用户看。
- 判定：四条同时成立 = 通过
- 证明方式：实机 + API 实测

## 判定口径

- 「自动出报告」= 停止请求之后，服务端在当前模块结束时即产出报告，**不等待**剩余
  模块；判据是「停止 → 报告就绪」的实测耗时显著小于整轮耗时，且报告覆盖数 < 请求数。
- 「不扣分」= 未检测模块在 `SCORE_PENALTY` 里扣 0 分；判据是比较含未检测项的报告
  健康分与同数据去掉未检测项后的健康分一致（不是看某个固定分值）。
- 「复用不重测」= 复用模块的关键指标与第一次运行逐项一致；判据是两次运行结果 JSON
  的对应字段相等（不是「看起来差不多」）。
- 「逐字节一致」= 文件级 `Compare-Object` 无差异，不是肉眼比对。
- 「实检 N/M 项」= 报告 Hero 的「检测范围」chip；**不是**报告 caption 里的
  「实检 N 项」（那是参与计分口径的旧文案，两者含义不同，别混）。
- 「未检测」= 既有状态值（灰色），本特性**不新增**模块状态值；判定时若看到
  「已取消」「已跳过」等新状态词即判不通过。
- 验证脚本的正则与引号风格必须对齐实现真实形态（属性用双引号、chip 文本内嵌标签
  等），避免假阳性；断言口径先对齐实现再写脚本。
