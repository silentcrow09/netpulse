# 报告/结果页原生重构（v1.25.0）· 验收要求

> 唯一依据：`docs/spec.md`。本文件只规定「验什么、怎样判定」，不规定「怎么实现」。
> 实现与测试代码不在本文件范围内；执行与结果由交付阶段负责。

## 场景级验收（端到端）

### S1 · 诊断完成自动进入原生报告视图（主链路）
- 前提：GUI 正常启动，主页可见
- 动作：发起一轮诊断 → 等待跑完自动进入报告视图
- 期望结果：
  1. 报告视图在主页面内渲染；DOM 中不再存在 `<iframe>`（含 `#g-frame`）；
     顶栏、导航与主页完全一致（同一页面，无双滚动容器、无双顶栏）；
  2. 结论区前置：健康分/等级/评语 + 算式行（与导出报告 Hero 同口径，如
     `92 / 100 ＝ 100 − 警告 4×2`）+ 元信息（耗时/检测范围/生成时间）；
  3. 双口径说明可见：「实检 N/M 项 · K 项参与计分」及豁免模块说明；
  4. 待办清单只列需关注项，条数/顺序/文案与导出 HTML 报告一致；
  5. 模块卡折叠口径沿用：有根因时只展开首要根因涉及的模块；无根因时按
     `PROBLEM_STATUSES` 展开；卡片可点击展开/收起；
  6. 跑完进入报告视图后进度轮询停止（无后台空转）。
- 判定：1–6 全部满足 → 通过
- 证明方式：场景验证（真实跑一轮 + DOM 检查）+ 人眼核对

### S2 · 部分报告（停止后）
- 动作：诊断进行中点「停止」→ 确认 → 收尾完成
- 期望结果：自动进入原生报告视图；部分报告口径正确呈现（检测范围 N/M 为本次请求
  项数、未检测项标注「未检测」且不扣分说明）；视图为原生渲染（无 iframe）。
- 判定：全部满足 → 通过
- 证明方式：场景验证

### S3 · 主页「查看上次报告」
- 前提：本轮进程内已有报告（`has_report` 为真）
- 动作：主页点「查看上次报告」
- 期望结果：进入原生报告视图，内容与刚才跑完看到的一致；进程刚启动且无报告时
  该入口不出现（既有逻辑不变）。
- 判定：全部满足 → 通过
- 证明方式：场景验证

### S4 · 现场检测 → 原生视图 + 四件套照旧
- 动作：现场检测填写提交 → 完成
- 期望结果：GUI 内展示走原生视图（无 iframe）；导出四件套照旧落盘
  （brief_v2 一页版 / 完整版 HTML / JSON / PDF，文件名规则不变）。
- 判定：全部满足 → 通过
- 证明方式：场景验证（检查落盘文件 + 视图 DOM）

### S5 · 盯障停止 → 原生盯障报告
- 动作：启动盯障 → 停止（或自然结束）→ 进入盯障报告
- 期望结果：
  1. 盯障报告视图原生渲染（DOM 无 `#mon-frame` iframe），与主界面同一视觉语言；
  2. 结论 banner（一句话结论 summary）+ 关键统计（网关/外网丢包率、中断、抖动段、
     DNS 失败、TCP 重传率等按数据有无呈现）+ 事件表 + 延迟双线（含丢包点标注）可见；
  3. 盯障三件套（CSV/JSON/HTML）照旧落盘，内容与改前逐字节一致。
- 判定：全部满足 → 通过
- 证明方式：场景验证 + golden 比对（M4/M6）

### S6 · 报告数据端点契约
- 动作：带 token `GET /api/report`；无报告时同样请求
- 期望结果：
  1. 无报告 → 404；
  2. 有报告 → 200 `application/json`，含渲染屏幕版所需全部要素（健康分/双口径/
     待办/图表数据/模块列表含展开标志/诊断结论/本机信息/元信息）；
  3. 载荷不含 `tech.raw_results` 与模块 `raw` 大对象（屏幕视图不需要的原始载荷不下发）；
  4. 盯障数据端点同理：未结束/未落盘 → 404 或既有等价语义；结束后返回投影 JSON。
- 判定：全部满足 → 通过
- 证明方式：机械检查（路由契约测试）

### S7 · 屏幕版与导出版口径一致
- 动作：同一固定 report fixture 分别走屏幕版数据投影与 `render_report_html_customer`
- 期望结果：健康分/等级、counts、summary、待办清单条数与文案、模块状态与
  key_metrics、豁免说明——两侧取值一致（同源函数产出，JS 不重算）。
- 判定：逐项一致 → 通过；任一不一致 → 不通过
- 证明方式：机械检查（口径一致性测试）

### S8 · 注入防护
- 前提：fixture 含恶意串（`<script>`、属性闭合 payload、恶意 SSID/主机名/DNS 名）
- 动作：数据投影 → 页面渲染
- 期望结果：恶意串不以可执行形式出现在 DOM（按文本显示）；页面资产闸
  （innerHTML 禁用、insertAdjacentHTML 白名单）零违例；`<script>` 数量与改前一致。
- 判定：零违例 → 通过
- 证明方式：机械检查（P5 闸 + DOM 断言测试）

### S9 · 导出链零回归（golden）
- 动作：固定 LAST_RUN fixture 渲染 customer / brief / brief_v2 / 盯障 HTML 四份
- 期望结果：与改前基线逐行（逐字节）一致——本特性不触碰导出渲染器，任何差异即回归。
- 判定：完全一致 → 通过
- 证明方式：机械检查（golden 测试，基线随本特性落库）

### S10 · 兼容契约回归
- 动作：`--json` 单跑、`--cli` 菜单、非 TTY 管道
- 期望结果：三者行为与改前一致（不进 GUI、输出契约不变）；resume/cancel 语义、
  三类活动互斥、`/api/shutdown` beacon 语义、token 鉴权全部不变。
- 判定：既有相关测试全绿 + 抽查通过
- 证明方式：机械检查（既有测试套件）
