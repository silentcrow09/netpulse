# 盯障实时窗口（v1.22.0）· 验收要求

> 唯一依据：`docs/spec.md`。本文件只规定「验什么、怎样判定」。
> 前一特性（本地 GUI 壳 v1.21.0）的 spec/verify 见 git 历史 `80d73be`。

## 场景级验收（端到端）

### S1 · 入口与配置
- 动作：启动 GUI → 主页
- 期望结果：
  1. 主页出现第 7 张卡「持续盯障」，说明文案与终端盯障语义一致；
  2. 点卡片进配置页：时长预设（10 分钟/30 分钟/1 小时）+ 自定义分钟输入 +
     外网目标（可空）+ 主动负载开关（默认关）；
  3. 自定义 0 分钟提交 → 回显「按最短 30 秒执行」；自定义 2000 分钟 → 回显
     「按 24 小时执行」（钳位语义与终端一致）；
  4. 终端 `py netpulse.py --monitor 45` 行为与 v1.21.0 一致（输出/退出码/
     三件套）。
- 判定：四条同时成立 = 通过
- 证明方式：实机跑 + 截图 + 终端对照

### S2 · 实时盯障页
- 前提：配置页选 10 分钟、默认目标、不开负载 → 开始
- 期望结果：
  1. 进入盯障页：大数字（已运行/总时长）前进，四路状态行（网关/外网/DNS/TCP）
     与终端 `progress_line` 口径一致（同刻数值允许采样时差）；
  2. 延迟双曲线出现且随时间前进；单次曲线载荷 ≤200 点/流；
  3. 事件计数条显示（可为 0），含「完整事件以结束报告为准」注记；
  4. 服务端节流生效：1s 轮询期间进度计算 ≤0.5 次/s、曲线重算 ≤0.2 次/s
     （以服务端计数器为证）；
  5. 此期间主页场景卡/现场检测/完整诊断禁用；直接 `POST /api/run` → 409。
- 判定：五条同时成立 = 通过
- 证明方式：实机跑 + 曲线载荷体积测量 + 服务端计数日志

### S3 · 停止按钮（提前终止）
- 前提：S2 盯障进行中（已运行 ≥1 分钟）
- 动作：点「停止盯障」→ 确认弹窗 → 确认
- 期望结果：
  1. 采集停止，页面转入报告页；报告含「提前终止」标注；
  2. 三件套落盘 `reports/`（monitor_* 命名），HTML 可打开、含 canvas 图表；
  3. 主页互斥解除（场景卡恢复可用）。
- 判定：三条同时成立 = 通过
- 证明方式：实机跑 + 文件核验

### S4 · 到时自动结束
- 动作：自定义 1 分钟跑一轮（不开负载）
- 期望结果：
  1. 到时自动结束转报告页；结论条显示 verdict/结论/建议（透传
     `_monitor_conclusion`，数值与 JSON 报告一致——同源比对）；
  2. 三件套落盘且命名规则不变；JSON 里 `summary` 与结论条数字一致；
  3. 「打开报告文件夹」弹出资源管理器；「返回主页」后互斥解除；
     再开一轮生成新报告（旧报告文件不被覆盖）。
- 判定：三条同时成立 = 通过
- 证明方式：实机跑 + JSON 与结论条数值比对

### S5 · 主动负载
- 动作：配置页开「主动负载」，跑 3 分钟盯障
- 期望结果：页面出现「60s 后开始 15s 下载负载」倒计时提示；负载期间与
  结束报告中出现负载 note（「主动负载: 15s 读取 X MB」语义）；不开负载的
  轮次无此提示。
- 判定：三条同时成立 = 通过
- 证明方式：实机跑（负载目标为公网大文件，产生下行流量属预期）

### S6 · 性能红线
- 动作：实跑 10 分钟盯障（默认档），页面保持打开轮询
- 期望结果：
  1. 全程 GUI 页面操作无卡顿；内存增长平缓（任务管理器观察，无持续跳涨）；
  2. 曲线始终只显示最近 10 分钟窗口（不随时间变密）；
  3. 服务端节流计数达标（S2.4 同款判据）。
- 判定：三条同时成立 = 通过
- 证明方式：实机 10 分钟 + 计数日志（86400s 上限的量级控制以 spec 技术形态
  的节流+滚动窗口设计为准，不实跑 24 小时）

### S7 · 终端回归
- 动作/期望：
  1. `py netpulse.py --monitor 45` 与 v1.21.0 行为一致（终端输出结构、
     Ctrl+C 提前结束、三件套落盘与自动打开逻辑）；
  2. `--monitor --target 相关参数组合`、菜单入口 `m` 照旧；
  3. `--monitor --capture slice`（有 Npcap 环境）照旧走终端确认与抓包链路，
     GUI 全程无抓包痕迹；
  4. 全量 pytest 绿（用例零改动）。
- 判定：四条同时成立 = 通过
- 证明方式：实机逐条 + pytest 输出

### S8 · 视觉验收（逐页人眼核对）
- 前提：对照 `design_ref/gui/monitor_design_v1.html` 定稿版
- 动作：配置页 / 盯障页 / 报告页 与设计稿并排比对
- 期望结果：
  1. 布局结构、信息层级与设计稿一致；字号真实；
  2. 状态语义色正确（✓ 绿 / ✗ 红 / 等待灰，源自 `STATUS_COLORS`）；
  3. 转义抽查：自定义目标输入恶意串（如 `<img src=x onerror=...>`）→
     页面不执行不破版（textContent 路径）；
  4. 零外链资源，断网可用。
- 判定：四条同时成立 = 通过
- 证明方式：逐页渲染截图人工核对 + 恶意串实测

## 判定口径

- 「与终端口径一致」= 同一时刻 `progress_line` 文本里的数值与 GUI 页面数值
  同源（服务端组装自同一 snapshot），采样时差 ≤5s 内允许数值不同。
- 事件计数的实时预览**不作为**精确判定依据（精确判定以结束报告为准，
  S4.2 的 JSON 比对是唯一数值闸）。
- S6 的内存观察为辅助证据；硬闸是节流计数与曲线载荷体积。
- 性能/节流类断言以**服务端计数器**为准，不以前端感知为准。
