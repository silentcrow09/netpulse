NetPulse 控制台界面现代化 — 方案稿

v1 · 2026-11-12 · 覆盖场景：双击 exe / cmd 运行的全部人读画面 · 交付物：本稿（选型后另出 spec.md + verify.md 再实施）

目标：让 CMD 窗口看上去更现代、更人性化。三个方案按改动幅度递增，可独立实施，也可 A+B 组合。 所有画面均为真实文案、真实字号（等宽 13.5px ≈ conhost/WT 默认观感）、真实 16 色映射（Campbell 色板）。 看稿方式：直接滚动浏览，黄色底=变更点，绿色底=新增内容，红色底=顺带修的问题。

黄 = 变更 绿 = 新增 红 = 修复 无标注 = 保持不变

  • 分隔线三种人格：=×60 当横幅、-×60 当页脚、另有闭环框/开式框两种提示框，没有一个统一的「框」语言。
  • 菜单列不对齐：三列菜单项起止位置随文字长度漂移；说明行缩进比其它行多一格。

  • 潜在乱码（顺带修复项）：Win7 老 conhost 不支持 VT 时，ANSI 颜色码会按字面打出 ←[90m。现在只有 --no-color 手动关色，应改成检测失败自动降级。

方案 A · 统一修饰

最稳

不动布局结构，只把「视觉语言」收敛成一套：统一边框与分隔线、统一语义色板、对齐菜单网格、修复 Win7 乱码。改动全在打印层，零交互变化，全部终端兼容。

工作量 小（约半天）
风险 低
兼容 Win7 conhost / Win10 conhost / WT / 管道 全兼容
效果幅度 约 40%

A-3 · 顺带修复（所有方案共享）

Win7 老 conhost（修复前后对比）
修复前:  ←[96m┌─ 异常自动上报 ──────────────←[0m   (ANSI 码按字面打出来)

  • 语义色板收口：新增 CLI_STATUS_COLORS（完成=绿 / 警告=黄 / 异常错误=红 / 超时=黄 / 未检测=灰），与 HTML 报告的 STATUS_COLORS 同语义，替换终端侧散落的 _severity_color 等局部映射（呼应 AGENTS.md「不要另立映射」）。

方案 B · 现代重排

推荐 = 方案 A 的全部内容 + 布局与反馈升级

在 A 的统一色板/边框基础上，重排关键画面：菜单卡片化、进度条实时化、完成屏结论前置。全部用 16 色 ANSI + \r 回车刷新实现，不依赖 Windows Terminal；老 conhost 自动降级为 A 的静态形态。

工作量 中（约 2 天）
风险 中低（进度条有 VT 检测降级路径）
兼容 全兼容：VT 可用→动态；否则→静态
效果幅度 约 75%

方案 C · 全屏 TUI

激进

进入备用屏幕缓冲区（alternate screen），方向键选择、实时刷新整屏。观感最接近现代 CLI 工具（如 Windows Terminal 里的 k9s/lazygit）。但依赖较全的 VT 支持，且需要处理「诊断输出与全屏 UI 抢屏」的调度，复杂度显著上升。

工作量 大（4-5 天）
风险 中高（conhost VT 子集差异、退出恢复现场）
兼容 Win10+ 优先；Win7/管道 自动降级为方案 B
效果幅度 约 90%

技术约束（实施时遵守）

约束说明

字符白名单只使用点阵字体有字形的字符：┌┐└┘│─ ✓✗⚠…█░■● ·»；不用圆角框 ╭、Braille ⠋（方案 C 特性单独降级）
